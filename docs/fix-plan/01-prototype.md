## A1. Токены и базовый CSS

**Источник:** отчёт 3.0 (контраст, фокус), 3.13 (токены), 3.9 (переключатели), 3.16 (forced-colors, шрифты), 3.17 (бейджи протоколов).

**Изменения:**

1. Токены в `html[data-theme="dark"]` и `html[data-theme="light"]` уже обновлены (см. `00-README.md`, раздел 2). Ничего в них не менять, кроме пунктов ниже.
2. Текст статусов — только через `*-text`-токены. Заменить в существующих правилах:
   - `.d-mid{color:var(--warn)}` → `color:var(--warn-text)`;
   - `.badge-warn{… color:var(--warn)}` → `var(--warn-text)`;
   - `.badge-info{… color:var(--info)}` и `html[data-theme="light"] .badge-info{color:var(--info)}` → `var(--info-text)` в обоих;
   - `.ll-info{color:var(--info)} .ll-warn{color:var(--warn)} .ll-error{color:var(--err)}` → `--info-text`, `--warn-text`, `--err-text`;
   - `.menu-item.danger{color:var(--err)}`, `.menu-item.danger .ic{color:var(--err)}`, `.btn-danger{… color:var(--err)}`, `.field-err{… color:var(--err)}`, `.field .req::after{… color:var(--err)}` → `var(--err-text)`;
   - в JS `renderStatus`: `state.style.color = S.conn==='on' ? 'var(--ok)' : …'var(--warn)'…` → `'var(--ok-text)'` и `'var(--warn-text)'`.
3. Границы интерактивных элементов (WCAG 1.4.11):
   - `.input,.select,.textarea{… border:1px solid var(--b-subtle) …}` → `var(--b-control)`;
   - `.chip{… border:1px solid var(--b-subtle) …}` → `var(--b-control)`;
   - выбранный сегмент различим не только фоном: добавить `.seg button.on{box-shadow:inset 0 0 0 1.5px var(--b-control);font-weight:600;color:var(--t1)}` (оба правила `.seg button.on` из v1.1 заменить этим);
   - переключатель `.sw` — по S1, блок «Переключатель».
4. Размеры целей (DS §12: ≥ 32 px; WCAG 2.5.8: ≥ 24 px): по S1, блок «Размеры». Ссылку «Копировать детали…» в карточке подписки заменить кнопкой `button.btn.btn-ghost.btn-sm` (задача A9).
5. Единое фокус-кольцо: по S1, блок «Фокус». У полей ввода допускается кольцо с `outline-offset:0` и `border-color:var(--accent)` (правило `.input:focus-visible,…` из v1.1 оставить).
6. Бейджи протоколов нейтральные: удалить правила `.bt-ss`…`.bt-https` (8 тёмных и 8 светлых `html[data-theme="light"] .bt-*`, а также `.bt-vless`) и добавить единое правило из S1, блок «Бейджи». Классы `bt-*` в разметке оставить (на них опираются JS и селекторы).
7. Цвет образцов акцента: `.accdot i.half-r{background:#4E7A63}` → `#466F59`; в разметке кнопки `data-accent="sage"` у `<i style="background:#4E7A63">` → `#466F59`.
8. Шрифты по ОС и режиму: S1, блок «Шрифты». Атрибуты `data-os` и `data-shell` у `<html>` выставляет задача A3.
9. Режим высокой контрастности: S1, блок «forced-colors», вставить перед `@media (prefers-reduced-motion: reduce)`.

**Готово, когда:** `token_contrast.py` — все PASS; в `a11y_sweep.py --quick` категория `contrast` содержит только элементы, которые удаляются или переделываются в A3/A4/A7 (titlebar, `#ppName`), и ни одного `.d-mid`, `.badge-info`, `.ll-*`, `.p-addr`, `.lt`; выключенный переключатель на `surface` виден рамкой 1,5 px `--b-control`.

|---|---|---|---|
| Язык | `#langSel` (перенести существующий `<select>`) | ru, zh, en, es, de; подписи из `LANG_NATIVE` («简体中文», а не «中文») | `applyLang` |

| Данные | сегмент | Демо / Первый запуск / Ошибки / Загрузка | `S.scenario` = `demo | empty | error | loading` (см. «Сценарии» ниже) |

Панель — `role="dialog"` не модальный, `aria-labelledby` на её заголовок «Стенд»; Esc закрывает; кнопка `#standBtn` имеет `aria-expanded`. Все подписи — ключи `stand.*` во всех языках. Панель не участвует в проверке `a11y_sweep` (атрибут `data-a11y-ignore` на корне панели) и не ловит Tab, когда закрыта (`inert`).

**Сценарии данных (`S.scenario`).** Задают состояние, которое рисуют экраны A7–A14:

- `demo` — текущие демонстрационные данные;
- `empty` — первый запуск: `PROFILES` и `SUBS` пусты (исходные массивы сохранить в `DEMO_PROFILES`, `DEMO_SUBS` и восстанавливать при возврате в `demo`), журнал пуст, соединений нет;

Хеш-параметр `data=demo|empty|error|loading` выставляет сценарий при загрузке.

**Готово, когда:** в шапке приложения нет ни одного контрола стенда; каждый пункт таблицы работает; `kbd_probe.py` не находит фокус внутри закрытого стенда; хеш `#data=empty` открывает прототип в сценарии «Первый запуск».

## A19. Веб-режим и вход

**Источник:** отчёт 3.12, 2.2 (веб-панель).

**Изменения:**

1. **Экран входа** `#webLogin` (внутри `#app`, поверх содержимого, только при `S.mode === 'browser' && !S.webAuthed`): знак, заголовок «Вход в LAVRay» (`web.login.t`), подпись «Роутер · 192.168.1.1» , поле «Пароль» (`label`, кнопка-глаз, `autocomplete="current-password"`), кнопка «Войти», переключатель «Запомнить это устройство на 30 дней» (`web.remember`). Пустой пароль — ошибка у поля; пароль `wrong` — «Неверный пароль. Осталось попыток: 4» (`web.login.bad`), после 5 неудач — «Вход заблокирован на 5 минут» (`web.login.locked`). При HTTP — плашка «Соединение не защищено. Включите HTTPS в настройках панели» (`web.insecure.long`). Любой другой непустой пароль — вход (`S.webAuthed = true`, не сохраняется после перезагрузки).
2. При переходе Стендом в режим «Браузер» вход показывается один раз за загрузку; кнопка Стенда «Вход в веб-панель» показывает его снова.
3. **Возможности платформы:** функция `caps()` возвращает набор `{tray, autostart, sysproxy, tunDesktop, gateway, processRules, hotkeysGlobal, windowControls}` по `S.mode` и `S.os`; все места, где интерфейс зависит от платформы, читают `caps()`, а не `S.mode` напрямую. В веб-режиме: главный экран — «Шлюз» вместо «Режима» (A7), процессные правила — с подписью «Не действует на роутере» (A10), Настройки — секция «Роутер» (A13), меню — пункт «Выйти» (`web.logout`).
4. Адресная строка браузера: `http://192.168.1.1:9090/` и плашка «Не защищено» (A3).

**Готово, когда:** в режиме «Браузер» без входа содержимое недоступно ни мышью, ни Tab (`inert` на остальном `#app`); после входа видны только применимые функции; «Выйти» возвращает на экран входа.

## A20. Движение и фон

**Источник:** отчёт 5.8; эталон — `design/concepts/brand-motion.html`.

**Изменения (код — S10):**

1. Токены движения в `:root`: `--e-std` (есть как `--ease`), `--e-in: cubic-bezier(.05,.7,.1,1)`, `--e-out: cubic-bezier(.3,0,.8,.15)`, `--e-spring: linear(…)` (значение в S10), длительности `--t-micro 120ms`, `--t-std 200ms`, `--t-emph 280ms`, `--t-chor 700ms`.
2. Переходы экранов по направлению (A5): вход 280 мс со сдвигом 10 px и шагом 32 мс для первых 6 дочерних блоков, выход 120 мс. Индикатор навигации и вкладок перетекает (`transform`, 280 мс, `--e-in`).
3. Диалоги: подложка — прозрачность 200 мс; окно — `scale(.98) → 1` и прозрачность 200 мс с `transform-origin` в точке кнопки-триггера (вычислить из `getBoundingClientRect` триггера относительно окна диалога). Закрытие — 120 мс. Панель профиля — сдвиг справа 280 мс, содержимое лесенкой.
4. Хореография подключения (A2): пунктир луча при подключении, прорисовка луча и вспышка зеркала при успехе, «пружина» фотона, одна волна по фону `.ripple` от знака (1 с). При обрыве — разрыв луча, красный фотон, тост с обратным отсчётом переподключения 3 с и кнопкой «Сейчас» (`toast.reconnect`).
5. Фон «световое поле» `#bgField` за содержимым `#main` (S10): два медленных луча и «пол», зерно 6 %; интенсивность от состояния (`off` 0,45; подключение 0,95; подключено 0,75; ошибка 0,30); «фотоны трафика» не чаще раза в 4 с при скорости > 300 КБ/с. Настройка «Фоновая анимация» (A13): Выкл — слоя нет; Тихая — только зерно; Живая — всё. По умолчанию: приложение — Живая, веб — Выкл. Пауза при `document.hidden` и при reduced motion.
6. Все новые анимации — только `transform` и `opacity`; при `prefers-reduced-motion: reduce` существующее глобальное правило их гасит; JS-циклы (фотоны, обратный отсчёт) проверяют `matchMedia('(prefers-reduced-motion: reduce)')`.

**Готово, когда:** `kbd_probe.py`: `reduced-motion-no-infinite-animations` PASS; при «Живой» фон заметен, но не мешает чтению (контраст `a11y_sweep` не ухудшился); в простое нет циклов `requestAnimationFrame` (проверка: `window.requestAnimationFrame` вызывается 0 раз за 2 с на экране «Настройки»).

## A22. Встроенная самопроверка доступности

**Источник:** отчёт 3.0 («тестируется автоматически» не было), чек-лист раздела 8.

**Изменения:** кнопка Стенда «Проверить доступность» вызывает `runA11yCheck()` (S11): проверяет текущее состояние экрана (контраст текстов к фону, цели < 24 px, элементы без имени) и пары токенов текущей темы; результат — в диалоге `#dlgA11y` списком «Нарушений: 0» или с перечнем элементов (селектор, значение, порог) и кнопкой «Подсветить» (обводит элемент на 2 с).

**Готово, когда:** на исправленном прототипе самопроверка показывает 0 нарушений на всех экранах; на копии v1.1 (`lavray/design/prototype.html` с этим же скриптом) находит нарушения `text.tertiary`.
