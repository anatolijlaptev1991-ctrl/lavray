| Поле | Значение |
|---|---|
| ID | M13 |
| Слой | ручной (человек; для агента с computer-use — только часть 1 и часть 3) |

## Состояние интерфейса на момент написания

RPC хвостов A (`RemoveUnavailableProfiles`, `DeduplicateProfiles`, `ResolveDomains`, `ExportConfig`, `ResetSettings`, `SubscribeSettings`) в ядре готовы, но **кнопок и пунктов меню для них в приложении ещё нет**: интерфейс для неиспользуемых RPC входит в хвосты B (фаза Ф6, выпуск 0.8.0). Поэтому дословных подписей для «Удалить недоступные», «Удалить дубликаты», «Разрешить домены», «Экспорт конфига» в `ru.ts` пока не существует, и этот файл не придумывает их. Что можно проверить вручную уже сейчас — части 1–3. Часть 4 (экран) отмечена `TODO` и дописывается после слияния хвостов B.

## Цель

1. Показать пользователю расхождение между понятием «недоступный сервер» в списке («Недоступные») и в очистке (задержка `< 0`): эталонный дефект сборки хвостов A, который автоматика A09 фиксирует как `FAIL`.
2. Проверить читателей настроек, видимых пользователю: размер буфера журнала (`ui.max_log_lines`, диапазон 100–50 000, по умолчанию 1000).
3. Проверить поведение «запоминания профиля» (`remember.id`, `remember.modes`) в приложении: после подключения и перезапуска выбранный сервер и режим сохраняются.
4. (TODO) Проверить экранные действия очистки, разрешения доменов и экспорта конфига.

## Предусловия

- Установленная версия `<TAG>` (по умолчанию `v0.9.0`; на момент написания — сборка с хвостами A).
- Три сервера-пустышки: «Серверы» → «Импорт» → «Ссылка»: `socks://127.0.0.1:1#m13-dead-1`, `socks://127.0.0.1:2#m13-dead-2`, `socks://127.0.0.1:3#m13-dead-3` (порты закрыты, подключиться нельзя).
- Для части 2 — запуск ядра с веб-панелью (см. M16, часть 1) и `curl.exe`.

## Безопасность

Системные настройки не меняются. Серверы-пустышки удаляются в части 5.

## Часть 4. TODO: экран хвостов B

Допишется после слияния хвостов B (интерфейс очистки, разрешения доменов и экспорта конфига). Планируемое содержимое, чтобы не потерять требования плана (раздел 6.2 и 7.1):

- меню группы или панель «Серверы»: действие очистки недоступных с пробным прогоном (список), подтверждением и отчётом, что пропущено (активный сервер, ссылки цепочек, непроверенные);
- действие «Удалить дубликаты»: пробный прогон, критерий дубликата (тип, адрес, порт, канон деталей; имя, заметки, теги не учитываются), оставляется первый по порядку, ссылки цепочек переписываются;
- «Разрешить домены»: адрес сервера превращается в IP, домен переходит в SNI или host, если они пусты; цепочки, custom-профили и уже-IP пропускаются; ошибки по каждому серверу в отчёте (`failed` с причиной);
- «Экспорт конфига» (рабочий и тестовый) с предупреждением «содержит секреты»; запрет для внешнего ядра (`naive`);
- кнопка сброса настроек к умолчанию; отображение читателей настроек;
- `win.sp_format` — формат строки прокси в системных настройках Windows (читает оболочка);
- `share.vmess_old_format` — формат ссылки VMess при «Копировать ссылку».
