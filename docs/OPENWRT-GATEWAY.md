# LAVRay — шлюз на OpenWrt

Создано по аудиту 2026-10 (`docs/AUDIT-CLAUDE-2026-10.md` §2.3, сырой отчёт `docs/audit-2026-10/raw/03` §3.3). Сопутствующие: `docs/UPDATE-SYSTEM.md` v2.0 §6 (обновления), `docs/THREAT-MODEL.md` (границы доверия панели), `docs/PLATFORM-MATRIX.md`.

## 1. Цели и поддержка

- Версии OpenWrt: **24.10** (пакеты ipk, usign) и **25.12+** (пакеты apk, обязательные подписи). Переход 25.12.0 с opkg на apk учтён везде: два фида, скрипт обновления определяет менеджер (UPDATE-SYSTEM v2.0 §6).
- Архитектуры: `x86_64`; `aarch64_cortex-a53` (MediaTek Filogic: GL.iNet MT3000/MT6000, Xiaomi AX3000T, Cudy); `aarch64_cortex-a72` (Raspberry Pi 4); `aarch64_generic`. Один статический Go-бинарь (`CGO_ENABLED=0`, минимальные build-теги), упакованный под каждую метку.
- `mipsel_24kc` (MT7621, 128 МБ RAM) — **явно не поддерживается**; при установке показывать понятное сообщение.
- Минимум: **256 МБ RAM** и **64 МБ свободного overlay** (или extroot).

## 2. Пакеты

| Пакет | Состав |
|---|---|
| `lavrayd` | ядро (Go-бинарь + API; procd-сервис) |
| `lavray-webui` | веб-панель (статика + серверная часть панели) |
| `luci-app-lavray` | приложение LuCI |

Зависимости: `kmod-tun`, `kmod-nft-tproxy`, `ca-bundle`. Имена пакетов одинаковы во всех документах проекта (аудит 2026-10 фиксировал расхождение — устарело).

## 3. Режим шлюза

Переключатель на главном экране веб-режима: «Шлюз: выкл / TProxy / TUN» (DS v1.2 §8).

**TProxy (рекомендуется для большинства роутеров).** Схема nftables как include fw4 (`/usr/share/nftables.d/`):

- таблица `inet lavray`; цепочки PREROUTING (tproxy на порт ядра, `meta l4proto {tcp, udp}`) и OUTPUT-исключения;
- исключения: `geoip:private` (не заворачивать LAN→LAN), адреса самого роутера, DHCP;
- трафик самого `lavrayd` исключается по `meta skuid` (отдельный системный пользователь `lavray`) или `meta mark`, чтобы не получить петлю;
- перехват DNS: порт 53 с LAN → dnsmasq пересылает на ядро, либо режим `hijack-dns` в правиле ядра; DoH-клиенты LAN не перехватываются — в per-device политике им соответствует правило «напрямую» или блок порт 853/443-DoH по желанию владельца;
- IPv6 — включается/выключивается **явно** (отдельная цепочка ip6; по умолчанию выключено, чтобы не устроить утечку всех v6-клиентов);

**TUN (альтернатива).** Виртуальный адаптер на роутере через `kmod-tun`; годится, когда TProxy недоступен; требует больше CPU на медленных платформах.

Отказоустойчивость правил — §5.

## 4. Устройства LAN

- Политики **на устройство** по MAC: «через прокси» / «напрямую» / «по пресету» (пресет применяется к трафику устройства, как региональные пресеты LAVRay).
- Гостевая сеть — по умолчанию «напрямую» (не проксировать чужих гостей).
- Список устройств — страница «Роутер → Устройства в сети» (ключи `router.*` прототипа v1.2); без политики устройство наследует общую.

## 5. Отказоустойчивость

- **Watchdog procd**: ядро упало или нет связи N минут → снять правила nftables (fw4-include деактивируется), интернет продолжает работать без прокси, уведомление в панели и логе; после восстановления ядра правила возвращаются.
- Обновление с watchdog: «нет связи N минут после обновления → откат на прошлый пакет» (UPDATE-SYSTEM v2.0 §6).
- Страж восстановления после краха (FR-UI-270): при старте снимаются осиротевшие правила и TUN.

## 6. Веб-панель и LuCI

- Привязка к адресу LAN из UCI (`lavray.@lavray[0].listen`), **не `0.0.0.0`** (WAN/гостевые зоны исключаются).
- Вход по паролю: Argon2id, сессия `HttpOnly; SameSite=Strict; Secure`, CSRF-токен, лимит попыток с backoff, выход (FR-UI-278).
- HTTPS с самоподписанным сертификатом; отпечаток показывается в LuCI при первой установке соединения; предупреждение «Не защищено» в шапке при HTTP (ключ `web.insecure`).
- Заголовки: CSP (без `*` в connect/frame), `frame-ancestors 'none'`, `nosniff`, `X-Content-Type-Options`.
- LuCI-приложение: клиентский JS + rpcd/ucode-бэкенд со своим ACL (минимальные права: чтение статуса, управлением шлюзом — отдельная привилегия).

## 7. Ресурсы

- `GOMEMLIMIT` и `GOGC` — под профиль устройства (меняются в UCI); «лёгкая» сборка с минимальными build-тегами sing-box.
- Статус и логи — в tmpfs (`/tmp/lavray/`), не в overlay: flash не изнашивается.
- geo-данные — не чаще раза в неделю (UPDATE-SYSTEM v2.0 §6); rule-set из кэша (`cache_file`, FR-UI-266).
- Отказ установки/обновления при свободном месте < 2× размера пакета.

## 8. Обновления

Единая точка: `docs/UPDATE-SYSTEM.md` v2.0 §6 — два фида (ipk+usign для 24.10, apk+подпись для 25.12+), ключ фида до первого обновления, `lavray-update` с выбором зеркала, локальное хранение прошлого пакета, watchdog-откат, обновление только пакетов LAVRay, tmpfs и лимиты geo.

## 9. Чего в этом документе нет (дальше)

- Точная nftables-грамматика include fw4 и юнит-файлы — фиксируются при реализации и становятся приложением к этому документу [проверь на реальном fw4 24.10/25.12].
- Матрица производительности TProxy/TUN по архитектурам — после первых бенчмарков (бюджеты — `docs/TEST-PLAN.md`).
> **Статус реализации (0.1.x).** Это спецификация. В репозитории есть заготовки `core/internal/gateway` (nftables-рендер, watchdog) и `core/internal/web` (вход в панель), но к ядру они не подключены; `GatewayService` и `WebSessionService` отвечают `unimplemented`. Пакетов `lavrayd`, `lavray-webui`, `luci-app-lavray` и фидов нет; работает только флаг `--headless`.
