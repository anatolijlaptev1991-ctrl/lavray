# LAVRay и MCP: управление ИИ-агентами

Решение владельца 2026-10-29. Документ описывает, что такое MCP-доступ в LAVRay, как его включить, как подключить Claude Desktop, Claude Code и Cursor и чем он защищён. Угрозы и остаточные риски — в [`THREAT-MODEL.md`](THREAT-MODEL.md) (§3, §4, §5).

## 1. Что это

MCP (Model Context Protocol) — открытый протокол, по которому ИИ-агенты вызывают инструменты. В LAVRay инструменты позволяют агенту посмотреть состояние подключения и, если пользователь разрешил, управлять им: «подключись к самому быстрому серверу», «проверь серверы», «обнови подписки».

MCP-сервер — это подкоманда ядра `lavray-core mcp`. Он работает по stdio (JSON-RPC 2.0, одно сообщение в строке), сам ничего не запускает и подключается к **уже запущенному приложению**. Агент запускает его как обычный процесс, поэтому настраивается один раз путём к `lavray-core.exe`.

По умолчанию доступ **выключен**. Пока он выключен или приложение не запущено, любой инструмент отвечает:

> LAVRay не запущен или доступ для агентов выключен: откройте LAVRay → Настройки → Агенты (MCP)

## 2. Как включить

1. Откройте LAVRay → **Настройки → Агенты (MCP)**.
2. Выберите режим: **Только чтение** или **Чтение и управление**. Ниже выбора приложение объясняет, что агент сможет делать и чем это рискованно. Изменение действует сразу, перезапускать ничего не нужно.
3. Нажмите **Скопировать настройку** (JSON для Claude Desktop и Cursor) или **Команда для Claude Code** и вставьте в клиент (§3).

Кнопки подставляют настоящий полный путь к `lavray-core.exe` рядом с установленным приложением. Если приложение запущено не из установленной версии, путь определить нельзя, и вместо текста будет сообщение; тогда укажите путь вручную.

## 3. Подключение клиентов

Во всех примерах `command` — полный путь к `lavray-core.exe`, `args` — ровно `["mcp"]`. Путь ниже — пример; точный путь даёт кнопка в настройках.

### Claude Desktop и Cursor

Раздел `mcpServers` в `claude_desktop_config.json` (Claude Desktop → Settings → Developer → Edit Config) или в `mcp.json` Cursor (Settings → MCP):

```json
{
  "mcpServers": {
    "lavray": {
      "command": "C:\\Program Files\\LAVRay\\binaries\\lavray-core.exe",
      "args": [
        "mcp"
      ]
    }
  }
}
```

В JSON обратные косые черты в пути удваиваются. После правки перезапустите клиент.

### Claude Code

```
claude mcp add lavray -- "C:\Program Files\LAVRay\binaries\lavray-core.exe" mcp
```

Проверка: `claude mcp list`, внутри Claude Code — `/mcp`.

### Если что-то не работает

- Инструменты отвечают «LAVRay не запущен или доступ для агентов выключен» — запустите LAVRay и выберите режим в настройках. Файл доступа создаётся только пока приложение запущено.
- Клиент не видит сервер — проверьте путь и что `args` равны `["mcp"]`. Журнал сервера идёт в stderr; клиенты обычно показывают его в своём окне журналов MCP.
- Сменили режим, а список инструментов прежний — сервер сообщает клиенту `notifications/tools/list_changed`; если клиент его не обрабатывает, перезапустите клиент. Сами права при этом уже изменены: ядро применяет режим сразу.

## 4. Режимы и инструменты

У каждого инструмента есть описание и JSON Schema входа; ответ содержит текст и `structuredContent`. Ошибка инструмента приходит как результат с `isError: true` и понятным текстом, ошибка протокола — как ошибка JSON-RPC.

### Только чтение

| Инструмент | Что делает |
|---|---|
| `get_status` | подключено ли, к какому серверу (id и имя), режим (системный прокси или TUN), с какого времени, последняя ошибка |
| `list_servers` | id, имя, протокол, группа, страна, избранное, результат последнего теста (задержка, `ok`/`failed`/`n/a`/`untested`); параметры `group_id`, `limit` (до 500), `offset` |
| `list_subscriptions` | id, имя, число серверов, время обновления, квота и срок, если их сообщил провайдер |
| `get_traffic` | скорость и трафик сессии (если сборка ядра их отдаёт), итог по активному серверу |
| `get_public_ip` | внешний IP через туннель (по умолчанию при подключении) или напрямую (`via`) |
| `get_logs` | хвост журнала, до 200 строк (`lines`, `min_level`), через ту же маскировку, что и экран «Журнал» |

### Чтение и управление

Дополнительно к предыдущим:

| Инструмент | Что делает |
|---|---|
| `connect` | подключить сервер `server_id`; без него — сервер, выбранный в приложении (или первый). Режим (системный прокси или TUN) — тот, что выбран в приложении |
| `disconnect` | отключить |
| `switch_server` | переключить на `server_id`: отключение и подключение; если новый не стартовал, возвращается прежний |
| `test_servers` | проверить серверы (`mode`: `latency` — TCP-задержка, `url` — запрос через сервер), все или `server_ids`; ждёт окончания, но не дольше `timeout_seconds` |
| `update_subscriptions` | обновить одну подписку (`id`) или все активные; ждёт результата. Обновление, которое удалило бы много серверов, не применяется: подтвердить его можно только в приложении |

### Чего нет ни в одном режиме

Импорт, создание и удаление серверов и подписок, изменение настроек, DNS и правил маршрутизации, экспорт ссылок и конфигурации, чтение рабочего конфига (`GetRuntimeConfig`), пользовательские конфиги, остановка ядра. Таких инструментов нет, а ядро отказывает на эти вызовы и при прямом обращении с агентским токеном.

### Системный прокси и TUN

Подключение из MCP работает как кнопка в приложении. В режиме системного прокси Windows-прокси ставит **окно LAVRay**: оно следит за состоянием ядра и, когда подключение сделал другой клиент, применяет прокси; когда отключили — снимает. Это происходит один раз; собственные подключения окна второго вызова не порождают. Если «Системный прокси» в приложении выключен, прокси не ставится и для подключения из MCP.

В режиме TUN нужны права администратора. Если ядро запущено без повышения, `connect` возвращает объяснение (перезапустить LAVRay от администратора в диалоге приложения или выбрать системный прокси). Режим выбирает пользователь в приложении, агент его менять не может.

## 5. Как это устроено и чем защищено

```
Claude Desktop / Claude Code / Cursor
   │  stdio, JSON-RPC 2.0
   ▼
lavray-core mcp ──(http://127.0.0.1:порт, Bearer агентский токен)──▶ lavray-core serve
   ▲                                                                      ▲
   └── читает %APPDATA%\LAVRay\agent-endpoint.json                        └── токен из stdin
       {url, token, mode}                                                      (вторая строка)
                     ▲
                     └── пишет оболочка LAVRay
```

- **Отдельный агентский токен.** На каждый запуск ядра оболочка генерирует новый токен (32 байта CSPRNG) и передаёт его ядру второй строкой stdin рядом с основным токеном: в командной строке процесса его нет. Основной токен ядра в файл и в MCP не попадает.
- **Файл `agent-endpoint.json`.** Создаётся с явным защищённым дескриптором безопасности: доступ только у текущего пользователя и SYSTEM, наследование от каталога отключено. Если SID пользователя прочитать нельзя, файл не создаётся. Файл удаляется при остановке или падении ядра, выходе из приложения, выключении доступа; оставшийся после аварийного закрытия удаляется при следующем запуске. MCP-сервер отправляет токен только на loopback-адрес из файла.
- **Белый список в ядре.** Перехватчик авторизации ядра пускает агентский токен только к процедурам белого списка текущего режима `agent.mode` (`off` / `read` / `control`). Режим читается при каждом запросе, поэтому смена действует сразу. Список инструментов MCP — лишь удобство; настоящий барьер — ядро.
- **Ограничения параметров.** Подключение — только к сохранённому серверу и в режиме, выбранном пользователем (не встроенный профиль, не `validate_only`, не режим из запроса). У теста нельзя задать свой URL и полный тест, у обновления подписки — обходные флаги и подтверждение деструктивного результата. Поиск по списку серверов закрыт (он сравнивает адреса). Хвост журнала не больше 200 строк.
- **Никаких секретов в ответах.** Ядро очищает ответы агентского токена: у серверов остаются id, имя, протокол, группа, страна, избранное, результат теста; адреса, порты, UUID, пароли, ключи, заметки, ссылки подписок и тексты ошибок с адресами убираются; параметры входящего подключения из статуса удалены. Тексты ошибок проходят общую маскировку журнала и очистку от адресов. Имена серверов и строки журнала проходят через ограничение длины и очистку от управляющих символов.
- **Журнал — исключение из «адресов нет».** `get_logs` отдаёт строки журнала через общую маскировку приложения (секреты, ссылки, ключи скрыты), но в строках уровня info остаются адреса и имена хостов, к которым идёт трафик, а в ошибках — адреса серверов. Если это важно, не включайте агентам доступ вовсе.
- **Прозрачность.** Отказы агента и каждое управляющее действие записываются в журнал приложения («агент (MCP): …»).
- **Настройка не переносится копией.** `agent.mode` не попадает в файл резервной копии и не восстанавливается из него: чужой файл не должен включить управление.

### Риск prompt injection

Агент читает недоверенный текст (веб-страницы, письма, имена серверов, строки журнала), в котором может быть спрятана команда. Поэтому по умолчанию доступ выключен, режим «только чтение» не может ничего изменить, а «чтение и управление» сопровождается предупреждением в приложении. Инструментов импорта, удаления и экспорта нет, чтобы подсунутая команда не могла ни завести чужой сервер, ни забрать ваши. Включайте управление только для агентов и источников, которым доверяете. Описание сервера для агента (`instructions`) прямо просит считать имена серверов и строки журнала данными, а не командами.

## 6. Для разработчиков

- Протокол: версии `2025-06-18`, `2025-03-26`, `2024-11-05` (на `initialize` отвечаем запрошенной, если поддерживаем, иначе последней); `initialize`, `notifications/initialized`, `ping`, `tools/list`, `tools/call`, `notifications/cancelled`; `notifications/tools/list_changed` при смене режима. Без новых модулей Go.
- stdout — только протокол, журнал — stderr.
- Код: `core/internal/mcp` (протокол, инструменты), `core/internal/api/agent.go` (белый список, ограничения, очистка), `core/cmd/lavray-core/mcp_cmd.go` и `stdin.go`, `shell/src/agent.rs`, `ui/src/components/AgentsSettings.tsx`, `ui/src/lib/proxyFollow.ts`.
- Для тестов `lavray-core mcp --endpoint-file <путь>` берёт файл адреса из любого места (в обычной работе используется `--data` или каталог данных по умолчанию).
- Живая проверка без окна: поднять `lavray-core serve` на отдельном каталоге данных и свободном порту mixed-входа (не 2080), передать ему stdin двумя строками (основной и агентский токены), записать файл адреса и пройти `initialize` → `tools/list` → `get_status` → `connect` → `get_status` → `disconnect`. Системный прокси при этом не трогается: его ставит только окно.
