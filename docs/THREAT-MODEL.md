# LAVRay — модель угроз

Составлено по аудиту 2026-10 (`docs/AUDIT-CLAUDE-2026-10.md` §2.2, сырые отчёты `docs/audit-2026-10/raw/03` §2/§4, `04`). Сопровождающие документы: `docs/SECURITY.md` (канал отчётов об уязвимостях), `docs/UPDATE-SYSTEM.md` v2.0 (канал обновлений), `docs/BUGS.md` (LNB-25…36), `docs/OPENWRT-GATEWAY.md` (шлюз). Дата: 2026-10. Статус: живой документ — пересматривать при каждом изменении поверхности атаки.

## 1. Активы

| Актив | Где живёт | Цена потери/утечки |
|---|---|---|
| Ключи и пароли серверов (профили) | локальное хранилище, защищённое системным keychain | доступ провайдера к серверам, деанонимизация |
| Токены подписок | там же + HTTP-запросы обновления | кража подписки, слежка за пользователем |
| Трафик пользователя (метаданные и содержимое) | туннель, DNS-запросы | деанонимизация, профилирование |
| Ключи подписи релизов | офлайн-токены root, онлайн-ключи CI | подписанное вредоносное обновление всем пользователям |
| Учётная запись GitHub (репозитории, Pages, Actions) | GitHub | подмена релизов, Pages, workflow |
| Веб-панель роутера (пароль, сессия, управление шлюзом LAN) | OpenWrt | перенаправление/перехват трафика всех устройств дома |

## 2. Субъекты

| Субъект | Уровень доверия | Что может |
|---|---|---|
| Провайдер подписки | **полудоверенный** | выдаёт произвольный контент (YAML, ссылки, заголовки, `nekoray://`-профили с `c_cfg`); заинтересован в правильном UA/HWID, но контент может быть скомпрометирован |
| Веб-страница в браузере пользователя | недоверенный | JS на localhost-портах (CSRF/CSWSH/DNS-rebinding), запись в буфер обмена, deep link, prompt-bomb |
| Локальная программа того же пользователя | недоверенный | чтение файлов профиля, подмена файлов в каталоге пользователя (скрипты и конфиги для помощника), доступ к loopback-прокси, чтение argv/env процессов |
| Другое устройство LAN (в т.ч. сосед по гостевой сети) | недоверенный | доступ к панели роутера и прокси, брутфорс пароля |
| Сеть/провайдер/DPI | недоверенный | MITM/DNS-подмена, подмена ответов подписки (заглушки), блокировка GitHub и зеркал, детект и деградация VPN |
| Злоумышленник с доступом к CI/аккаунту | недоверенный | подмена артефактов, workflow, Pages; кража секретов Actions |
| Российские сервисы, выполняющие методичку Минцифры (апрель 2026) | недоверенный | проверка IP/ASN-репутации и признаков VPN на устройстве; отказ в обслуживании «замеченным» |

## 3. Границы доверия

| Граница | Протокол | Правило |
|---|---|---|
| UI ↔ Rust-оболочка | IPC Tauri (не сеть) | токен ядра не доступен JS; capabilities минимальны для каждого окна; CSP `default-src 'self'`; без `dangerouslySetInnerHTML` |
| Rust ↔ ядро | unix-socket (0600, каталог 0700) / named pipe с ACL | десктоп — без TCP-листенеров вообще; порт 0, токен — через stdin/inherited fd |
| Ядро ↔ привилегированный помощник | аутентифицированный IPC + allowlist | помощник принимает только валидированный конфиг; никакие пути/команды от клиента; конфиг — не файлы пользователя (LNB-26/27) |
| Приложение ↔ источники обновлений | HTTPS + подписи TUF-lite | доверие даёт подпись, не хост; зеркала из подписанного `sources.json` (UPDATE-SYSTEM v2.0) |
| Веб-панель ↔ браузер в LAN | HTTPS (self-signed + отпечаток), пароль Argon2id | bind на адрес LAN из UCI; сессия `HttpOnly; SameSite=Strict; Secure`; CSRF-токен; CSP `frame-ancestors 'none'` |

## 4. Таблица угроз

| Угроза | Вектор | Мера | Где в архитектуре | Тест |
|---|---|---|---|---|
| Подписка → RCE | `nekoray://`-профиль несёт `c_cfg`/`c_out`/`core`; MergeJson без фильтра; `external_ui_download_url` распаковывает zip без защиты от `..`; срабатывает в тесте задержки (LNB-25) | игнор `c_cfg`/`c_out`/`core`/`cmd` у импортированных (opt-in с diff); allowlist ключей merge; патч `downloadZIP` (запрет `..`, абсолютных путей, симлинков, лимит) | парсер подписок + билдер ядра + патч форка sing-box | подписка с `c_cfg` → поля отброшены; zip `../../x` → отказ; FR-UI-257 |
| CSRF / CSWSH / DNS-rebinding к localhost | страница в браузере шлёт запросы на `127.0.0.1:порт`, порт перебирается из JS; WS не защищён SOP | десктоп без TCP-API (unix-socket/pipe с проверкой владельца); при TCP: проверка Host/Origin/Content-Type, кастомный заголовок, токен, CORS без `*`; не копировать clashapi (CORS `*`, токен WS в query) | транспорт UI↔Rust↔ядро; сырой отчёт 03 §4 | автотест: `fetch` со страницы-злоумышленника на все локальные порты → отказ |
| Перебор пароля панели | брутфорс входа веб-панели роутера | Argon2id; лимит попыток с backoff и блокировкой; сессия `HttpOnly; SameSite=Strict; Secure` + CSRF-токен | веб-панель (FR-UI-278, OPENWRT-GATEWAY §6) | тест: N неудачных попыток → блок; cookie-флаги; CSRF без токена → 403 |
| Подмена файлов для помощника | root/админ исполняет скрипт/конфиг из каталога пользователя; `pkexec setcap` из PATH; setcap на переносимый бинарь (LNB-26/27) | помощник в защищённом каталоге; конфиг по IPC + allowlist; абсолютные пути; systemd `AmbientCapabilities`; GUI не повышается | привилегированный помощник (FR-UI-269) | подмена `vpn-run-root.sh` → отвергнуто; PATH с ложным `setcap` → не вызван |
| Loopback-SOCKS без пароля | локальный SOCKS5/HTTP без auth (урок апреля 2026): любое приложение узнаёт exit-IP и обходит split-tunnel | пароль обязателен при доступе из LAN; в TUN — без слушателей на loopback вообще; случайный порт + ACL по PID/UID где возможно (FR-UI-279) | inbound-менеджер + режимы | сканер: в TUN нет слушателей; в режиме прокси слушатель требует auth |
| Утечка секретов в логах | `core_config` при `-debug`, env/argv внешних ядер, результат QR, URL с токенами в ошибках (LNB-28, LNB-01) | единый `redact()` на входе всех логов; запрет логировать env/argv/конфиг; `without_url()`; экспорт журнала маскируется | слой логирования | контрактный «секрета нет ни в одной строке» |
| XSS из имён профилей → IPC | имя/заметка/лог-строка управляют UI; XSS в webview = контроль IPC (в прототипе ~30 `innerHTML` с `esc()`) | запрет `dangerouslySetInnerHTML`; только `esc()`; санитайзер markdown без картинок и `javascript:`; нормализация управляющих и BiDi | UI-слой (React) | фазз имён профилей разметкой; axe-core; сырой отчёт 03 §4 |
| Deep link импорта | `lavray://` вызывается любой страницей/программой; аргумент приходит в командной строке | только `lavray://import?url=…`; строгий разбор; всегда предпросмотр + подтверждение + rate-limit; никаких start/stop/update/settings (FR-UI-280) | роутер deep link в Rust | автотест: `lavray://start` и инъекции аргументов → отказ |
| Подмена буфера обмена | вредоносная страница пишет ссылку в буфер; авто-чтение видит чужие данные | чтение только по действию пользователя или при фокусе и строгом префиксе; диалог «Импортировать?»; предупреждение о секрете после копирования | окно импорта | UI-тест: буфер не читается в фоне |
| Компрометация канала обновлений | кража ключа, CI, аккаунта; freeze/replay/mix-and-match/downgrade | TUF-lite: root 2-из-3 офлайн, timestamp ≤7 дней, монотонный serial, подписанный sources.json, rollback-помощник | UPDATE-SYSTEM v2.0 (C4) §2–4, §10 | набор CI-тестов §10 |
| Подмена rule-set / geo | `.srs` с изменяемой ветки без хеша, `download_detour: direct` (LNB-31) | вендоринг в подписанный `geo.json` с sha256; detour через прокси; `cache_file` + встроенные наборы | менеджер geo-активов, FR-UI-266 | подмена на зеркале → отвергнуто по хешу; старт без сети |
| Утечки DNS/IPv6 | запросы мимо туннеля, IPv6 напрямую | раздельный DNS по пресету; DoH через туннель; FakeIP для TUN; strict route; проверка утечек в «Диагностике» (FR-UI-273) | билдер DNS + диагностика | автотест утечек на стенде; ручной чек-лист |
| Детект VPN российскими сервисами | IP/ASN-репутация; признаки на устройстве: имя адаптера (`tun`/`wg`/`utun`), порты, системный прокси, MTU (методичка Минцифры, апрель 2026 [проверяй актуальность]) | настраиваемое имя адаптера; «RU напрямую» в пресетах по умолчанию; самопроверка «заметности» с one-click фиксами | пресеты, настройки TUN, диагностика | ручной тест на сервисах-детекторах; юнит на подстановку имени адаптера |
| Захват порта / TOCTOU | предсказуемый порт ядра или панели (LNB-20) | порт 0 с выделением ОС; фактический адрес — из вывода ядра; для панели — конфликт обнаруживается и меняет порт | менеджер ядра | стресс-тест занятых портов |
| Паника ядра = смерть туннеля | panic в горутине (соль расшифровки ссылок, `getBetweenStr`, nil-deref Test) убивает весь сайдкар (LNB-13/32) | recover-интерсептор на всех RPC; валидация входа; явные границы слайсов | Go-ядро | фазз-цели; kill -9 → страж восстановления (FR-UI-270) |

## 5. Остаточные риски и решения владельца

| Риск | Что остаётся | Решение владельца |
|---|---|---|
| XHTTP не поддерживается штатным sing-box | пользователи RU-провайдеров на XHTTP не подключатся | три варианта: форк ядра с XHTTP / Xray как доп. ядро только для XHTTP / «не поддерживается» с понятным сообщением (FR-UI-281) |
| Подпись кода из РФ недоступна/дорога | SmartScreen/Gatekeeper/AV отпугивают пользователей | юрлицо или партнёр за рубежом; SignPath Foundation [проверь допуск VPN-инструментов]; до подписи — воспроизводимые сборки + minisign + чексуммы на нескольких площадках (отчёт 5.5) |
| Ключи стороннего клиента в репозитории | риск DMCA-takedown всего репозитория | согласие правообладателей ключей / вынос расшифровки в отдельный необязательный модуль вне основного репозитория / не включать в сборки по умолчанию (LICENSES.md, «Правовые вопросы владельцу») |
| Методичка Минцифры расширяет детект | «заметность» VPN растёт (TLS-fingerprint, active probing) | приоритет оркестратора устойчивости (fallback транспортов/портов) и self-check; следить за практикой [проверяй] |
| Полудоверенный провайдер настаивает на HWID | приватность vs совместимость с панелями | HWID только opt-in, случайный per-install ID (FR-UI-265) — уже решено; пересматривать при давлении панелей |
| Один мейнтейнер | bus-factor: аккаунт, ключи, зеркала | org-владение, root-ключи у 2–3 человек, зеркало вне GitHub (урок nekoray, отчёт 04 §d.7) |
