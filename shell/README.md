# shell/ — Tauri 2 оболочка LAVRay

Rust-оболочка на **Tauri 2**: нативный каркас приложения (окно, трей, системная интеграция)
и жизненный цикл Go-ядра.

## Зоны ответственности

- **Жизненный цикл ядра:** запуск бинаря `lavray-core` как дочернего процесса, контроль
  здоровья (heartbeat), перезапуск с экспоненциальной задержкой, гарантированное завершение
  (никаких осиротевших процессов), передача порта/токена ConnectRPC.
- **Нативный каркас:** окно (мин. 880×560, стартовое 960×640), кастомный титл-бар, трей-иконка (шеврон-глиф 16px),
  системный прокси. В разработке: автозапуск, deep-link `lavray://`, обновления приложения
  (автомат состояний `src/updater.rs` без сети; см. `../docs/UPDATE-SYSTEM.md`).
- **Шлюз IPC:** UI (React) ↔ команды Tauri ↔ ConnectRPC ядра; стриминг статистики/логов.

## Каркас (этап 3, скаффолд)

Компилируемый скаффолд по `../docs/stage3/shell-lifecycle.md` §10: Tauri 2,
`src/coreproc/` (FSM ядра §2, backoff, лог-ring §4, детекторы teardown §6 —
заглушки), `src/tray.rs` (конфиг меню §9), `src/uiprotocol.rs` (протокол
UI↔shell, версия в константе; имя `ipc` свободно под Connect-клиент ядра),
`src/updater.rs` (автомат обновлений §8.3). Интеграция с Go-ядром — `coreproc::driver`
(запуск реального процесса `lavray-core`; `MockCoreProcess` — для тестов); окно грузит
собранный UI (`build.frontendDist = ../ui/dist` в `tauri.conf.json`). `src/tray.rs` и
`src/updater.rs` — спецификация меню и автомат состояний, к рантайму пока не подключены.

```sh
cargo build                      # отладочная сборка
cargo test                       # юнит-тесты (без GUI)
cargo clippy --all-targets -- -D warnings
cargo tauri dev                  # окно с заглушкой (нужен tauri-cli)
```

Иконки-заглушки: `icons/gen-icons.ps1` (шеврон-глиф).

## Права администратора, автозапуск и флаги запуска (T-81, T-82)

Службы для TUN нет (как в NekoBox): TUN работает, когда приложение, а с ним и ядро (дочерний
процесс), запущено от администратора. Команды оболочки:

- `is_elevated` — есть ли у процесса права администратора;
- `relaunch_elevated` — запустить свой exe через UAC и выйти обычным путём (ядро остановлено,
  системный прокси возвращён); отказ в UAC даёт ответ `cancelled`, приложение остаётся как было;
- `autostart_state`, `set_autostart` — автозапуск с системой, состояние всегда читается из ОС:
  с правами администратора — задача планировщика `LAVRay` (вход пользователя, повышенный запуск),
  без прав — значение `LAVRay` в `HKCU\...\Run`; запуск командой `"<exe>" --tray`.

Флаги командной строки (`src/launch.rs`): `--tray` — окно скрыто, только значок;
`--elevated-relaunch` — экземпляр запущен перезапуском от администратора;
`--wait-pid=<pid>` — до инициализации плагинов дождаться выхода этого процесса (до 20 с), иначе
single-instance отдал бы аргументы старому окну. При удалении приложения хук NSIS
(`windows/hooks.nsh`) убирает оба вида автозапуска.
