# M19. Автозапуск с правами и автоподключение при запуске (0.9.2)

| Поле | Значение |
|---|---|
| ID | M19 |
| Слой | ручной (человек; агент с computer-use выполняет шаги на экране, вход в Windows и отключение сети делает человек) |
| Время | 90–120 минут (много выходов из системы и перезагрузок) |
| Зависимости | M01 (установленная версия), M02 и M03 (рабочий сервер, режимы «Системный прокси» и TUN), M06 (трей, уведомления), M09 (набор маршрутов), M17 (раздел «Агенты (MCP)»). Автоматика: A04 (Rust-тесты `autostart` и `connect_last` на фейках), A05 (`AutoConnectRow`, `usePendingConnect`, `pendingConnect`, `tunRelaunch`), A09 (подключение «последнего» по API). Автотесты не трогают вход в Windows, планировщик заданий и реестр: это проверяется только здесь |
| Опасность | **прокси, TUN, планировщик заданий, реестр**: шаги меняют автозапуск (`HKCU\...\Run`, задача `LAVRay-<SID>`), несколько раз выводят из системы и перезагружают ПК, включают TUN. Только тестовый ПК (`C:\lavray-test\TESTPC_OK`), лучше ВМ со снимком |

> **Предупреждение.** Если после проверки остался включённым системный прокси на мёртвый порт, выполните откат (часть 12). Задача `LAVRay-<SID>` создана с правами администратора: удалить её можно только из окна администратора.

## Цель

Проверить исправление 0.9.2: автозапуск установленной версии получает права администратора после одного запуска LAVRay от администратора (задача планировщика вместо значения `Run`), а настройка «Подключаться автоматически при запуске» (**«Настройки» → «Общие»**) один раз после входа в Windows поднимает последнее удачное подключение: тот же сервер и режим, без кликов, без всплывающих окон и без вечных повторов. Критерии К1–К13 повторяют по порядку раздел 8 «Критерии приёмки нативного исправления» разбора `LAVRay_0.9.1_autostart_autoconnect_analysis.md`.

## Предусловия

- **Тестовый ПК подтверждён.** Первая команда файла: `. C:\lavray-test\env.ps1; Test-TestPc` должна напечатать `True` (`01-ENVIRONMENT.md`, раздел 3). Иначе весь файл `BLOCKED`.
- Версия `<TAG>` (по умолчанию `v0.9.2`), **установленная** установщиком (`C:\Program Files\LAVRay`, M01), и portable-копия из ZIP релиза (`C:\lavray-test\portable\0.9.2`).
- Есть рабочий сервер `S1` (M02, M03), хотя бы раз удачно подключённый в нужном режиме: «последнее удачное подключение» запоминается только после успеха. Учётная запись Windows — администратор с запросом UAC.
- Снимок ВМ перед частью 1. Для части 6 нужен способ отключить сеть на ВМ.
- Если для 0.9.1 вручную делалась внешняя задача автоподключения (Python, VBS, скрипт MCP в планировщике или в «Автозагрузке»), она перекроет результат. Найдите её: `Get-ScheduledTask | Where-Object { $_.TaskName -notmatch '^(LAVRay-|Microsoft)' } | Select-Object TaskName, TaskPath`, и удалите из окна администратора до проверки.
- Экспорт реестра **до части 1**: `reg export "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" C:\lavray-test\tmp\M19-before.reg /y`.

Команды-наблюдатели (используются во всех частях):

```powershell
# автозапуск: значение Run и задача планировщика
(Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run' -ErrorAction SilentlyContinue).LAVRay
Get-ScheduledTask | Where-Object TaskName -like 'LAVRay-*' | Select-Object TaskName, State
# прокси и процессы
Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' | Select-Object ProxyEnable, ProxyServer
Get-Process lavray-shell, lavray-core, powershell, cmd, conhost -ErrorAction SilentlyContinue | Select-Object Name, Id, StartTime
# адаптер TUN и порт прокси
Get-NetAdapter | Where-Object InterfaceDescription -match 'wintun|sing|lavray'
Get-NetTCPConnection -LocalPort 2080 -State Listen -ErrorAction SilentlyContinue
```

## Часть 1. Включение: автозапуск с правами (К1, К8)

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 1.1 | Запустите LAVRay **без** прав администратора (обычный ярлык). «Настройки» → «Общие» → «Автозапуск с системой», включите | Включено; под переключателем пояснение, что автозапуск обычный, без прав администратора (для TUN понадобится перезапуск от администратора) | |
| 1.2 | Команды-наблюдатели | Значение `Run\LAVRay` есть, задачи `LAVRay-<SID>` нет | |
| 1.3 | Закройте LAVRay (трей → «Выход»). Запустите его **от имени администратора** (ПКМ → «Запуск от имени администратора», UAC «Да») | Приложение открылось; под переключателем автозапуска пояснение, что автозапуск будет задачей планировщика с правами администратора | |
| 1.4 | Подождите 5–10 секунд, команды-наблюдатели | Задача `LAVRay-<SID>` **создана**, значения `Run\LAVRay` **нет** (миграция Run → задача прошла сама). В «Настройках» состояние: включён с правами администратора (задача планировщика) | |
| 1.5 | `schtasks /Query /TN "LAVRay-<SID>" /XML` (SID: `whoami /user`) | В XML: запуск при входе пользователя, наивысшие доступные права, действие — `C:\Program Files\LAVRay\LAVRay.exe`. Повторный запуск 1.3 не создаёт вторую задачу | |
| 1.6 | Закройте приложение, запустите его обычным ярлыком (без прав) и откройте «Настройки» | Автозапуск показан включённым (задачу видно без прав); переключатель не сбрасывается | |
| 1.7 | Выключите автозапуск, не имея прав администратора | Понятная ошибка вместо падения: задача создана с правами администратора, запустите LAVRay от администратора и повторите; задача осталась | |
| 1.8 | Выключите, затем снова включите автозапуск из LAVRay, запущенного от администратора | Выключение удаляет задачу; включение создаёт её; значения `Run` нет | |

## Часть 2. Вход в Windows с задачей, без кликов (К1, К13)

Подготовка: автозапуск включён (задача, 1.8); «Подключаться автоматически при запуске» **включено**; в LAVRay, запущенном от администратора, подключитесь к `S1` в режиме **TUN**, нажмите «Отключить» и снова «Подключиться» и не отключайте: так запомнится последнее удачное подключение. Выйдите из LAVRay («Выход»).

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 2.1 | Сделайте «Выйти» из Windows (не перезагрузку) и войдите снова; **ничего не нажимайте** и не открывайте LAVRay вручную | Через 10–40 секунд запущены `lavray-shell` и `lavray-core`, в трее иконка LAVRay; запроса UAC нет | |
| 2.2 | Команды-наблюдатели | Адаптер TUN существует; оболочка запущена с повышением (диспетчер задач, «Повышенные права» = «Да»); системный прокси не включён (режим TUN) | |
| 2.3 | Откройте окно из трея | «Подключено», сервер `S1`, режим TUN, таймер сессии идёт; сообщений об ошибке нет | |
| 2.4 | `curl.exe https://api.ipify.org` | Адрес выхода `S1`, не прямой адрес ПК | |
| 2.5 | Наблюдайте экран с момента входа до появления иконки в трее (запись экрана) | **Нет** окон PowerShell, cmd, conhost, Python, Windows Script Host; кроме обычных уведомлений LAVRay ничего не всплывает | |

## Что собрать

Вывод команд-наблюдателей до и после входа (части 1, 2, 9), XML задачи (1.5), запись экрана входа в Windows до появления иконки в трее (2.5), скриншоты «Настройки» → «Общие» во всех состояниях автозапуска, фрагмент «Журнала» (части 5–6), значения `ProxyEnable` и `ProxyServer` в 6.4 и 11.4.

Шаг 12.2.

## Отчёт

`results/M19.md` по `templates/REPORT.md`; шаги — номера таблиц. Серьёзность: К11 (мёртвый системный прокси после сбоя), К7 (циклы UAC или перезапусков), К4 и К5 (буря повторов, занятый процессор) — `critical`; К1, К3, К6, К8, К12 — `major`; К2, К9, К10 — `major`; К13 — `minor`.

## Для агента с computer-use

Вход и выход из Windows, перезагрузки и отключение сети на ВМ делает человек; агент после входа снимает экран, выполняет команды-наблюдатели и заполняет таблицы. Часть 8 и шаг 9.5 на физическом ПК без снимка не выполнять.
