# M05. Свои поля конфига (Custom JSON) и окно подтверждения

| Поле | Значение |
|---|---|
| ID | M05 |
| Слой | ручной (человек или агент с управлением экраном) |
| Время | 20–30 минут |
| Зависимости | M01 (программа запущена). Для шагов подключения — рабочий сервер из M02/M03 (необязательно: основная часть работает на сервере-пустышке) |
| Опасность | нет для системы. Часть 6 (подключение) может включить системный прокси: делайте её с выключенным переключателем «Системный прокси» (см. M03, п. 5.4) |

## Цель

Проверить подтверждение пользовательского JSON (T-08B, Ф1): поля «Custom outbound JSON» и «Custom config JSON» в редакторе сервера, проверка формата и размера, окно «Подтверждение custom-полей» со списком изменений, галочка «Я понимаю, что это изменяет конфиг», кнопка «Применить», бейдж «custom: не подтверждено», сброс подтверждения при правке содержимого (но не при переименовании), и что без подтверждения свой JSON к подключению не применяется. Покрывает живую проверку Ф1 п. 1 и релизные заметки 0.3.0.

## Предусловия

- **Тестовый ПК подтверждён — для части 6.** Перед части 6 выполните `. C:\lavray-test\env.ps1; Test-TestPc`: должно напечатать `True` (маркер `C:\lavray-test\TESTPC_OK` есть, создан на этом ПК, не старше 30 суток). `False` — части 6 получает `BLOCKED`, остальные части выполняются.
- Раздел «Серверы» с хотя бы одним сервером. Создайте сервер-пустышку: «Серверы» → «Импорт» → «Ссылка» → вставьте `socks://127.0.0.1:1090#m05-test` → «Импортировать» (строит предпросмотр) → «Добавить» (записывает сервер).
- Тексты для вставки (сохраните в блокноте):

  - корректный JSON исходящего: `{"connect_timeout": "7s"}`
  - другой корректный JSON: `{"connect_timeout": "9s"}`
  - эквивалент первого с пробелами и другим порядком ключей: `{ "connect_timeout" : "7s" }`
  - не объект: `[1, 2, 3]`
  - синтаксическая ошибка: `{"a": 1,}`
  - JSON с изменением входящих: `{"inbounds": [{"type": "mixed", "tag": "extra-in", "listen": "0.0.0.0", "listen_port": 12345}]}` (для поля «Custom config JSON»)

## Безопасность

JSON с `inbounds` не подтверждайте и не подключайтесь с ним: он открыл бы порт в сети. Его нужно только просмотреть в окне подтверждения и отменить.

## Часть 1. Поля и проверка ввода

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 1.1 | «Серверы» → строка `m05-test` (щелчок по имени) | Открывается «Редактирование профиля» | |
| 1.2 | Прокрутите до раздела «Свои поля конфига» | Два поля: «Custom outbound JSON» (подсказка «Объединяется с исходящим профиля. Пусто или {} — не используется.») и «Custom config JSON» (подсказка «Объединяется с корнем конфига sing-box; ядро применяет только разрешённые ключи. Пусто или {} — не используется.»); примечание «После сохранения откроется список изменений конфига: custom-поля применяются только после вашего подтверждения.» | |
| 1.3 | В «Custom outbound JSON» введите `{"a": 1,}` | Под полем: «Ошибка синтаксиса JSON: строка 1, столбец N» (с числами строки и столбца); кнопка «Сохранить» заблокирована или сохранение отклоняется | |
| 1.4 | Введите `[1, 2, 3]` | Сообщение вида «Нужен JSON-объект: { … }» | |
| 1.5 | Вставьте текст длиннее 256 КиБ (в PowerShell: `('{"k":"' + ('x' * 270000) + '"}') \| Set-Clipboard`, затем Ctrl+V) | «JSON больше 256 КиБ» | |
| 1.6 | Очистите поле или оставьте `{}` и нажмите «Сохранить» | Сохраняется без окна подтверждения (пустое содержимое не требует подтверждения); бейджа нет | |

## Часть 2. Окно подтверждения

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 2.1 | Откройте редактор, в «Custom outbound JSON» введите `{"connect_timeout": "7s"}`, нажмите «Сохранить» | Открывается окно «Подтверждение custom-полей» с подзаголовком «Профиль: m05-test» и текстом «Custom-поля меняют итоговый конфиг sing-box. Проверьте изменения: пока вы их не подтвердите, они не применяются.»; сначала «Загружаем изменения…» | |
| 2.2 | Содержимое окна | Область «Изменения конфига (diff)» с построчным diff (удалённые строки с «−», добавленные с «+»; пароли, ключи и заголовки авторизации скрыты); список «Затронутые ключи» содержит путь с `connect_timeout`; чекбокс «Я понимаю, что это изменяет конфиг»; кнопки «Применить» и «Отмена» | |
| 2.3 | Состояние кнопки «Применить» без отметки | Заблокирована | |
| 2.4 | Esc | Окно закрывается без подтверждения; фокус возвращается; у сервера в списке бейдж «custom: не подтверждено» | |
| 2.5 | Нажмите на бейдж | Снова то же окно | |
| 2.6 | Отметьте «Я понимаю, что это изменяет конфиг» и нажмите «Применить» | Окно закрывается; бейдж исчез | |
| 2.7 | Откройте окно подтверждения для того же содержимого ещё раз (отредактируйте и сохраните без изменений) | Либо окно не открывается, либо сообщает «Это содержимое уже подтверждено. Повторное подтверждение ничего не изменит.» | |
| 2.8 | Окно доступности: Tab/Shift+Tab | Фокус не выходит за пределы окна (ловушка фокуса); читалка называет диалог «Подтверждение custom-полей» | |

## Часть 3. Что сбрасывает подтверждение

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 3.1 | Переименуйте сервер (поле «Название») в `m05-test-renamed`, сохраните | Подтверждение **сохраняется**: бейджа нет, окно не открывается | |
| 3.2 | Измените JSON только пробелами и порядком: `{ "connect_timeout" : "7s" }`, сохраните | Подтверждение сохраняется (канонический вид тот же) | |
| 3.3 | Измените значение: `{"connect_timeout": "9s"}`, сохраните | Открывается окно подтверждения заново; бейдж «custom: не подтверждено» | |
| 3.4 | Откройте окно, закройте через «Отмена»; затем верните `{"connect_timeout": "7s"}` (то, что подтверждали раньше) и сохраните | Подтверждение **не** возвращается само (A→B→A снимает его): снова окно и бейдж | |
| 3.5 | Подтвердите снова | Бейдж исчез | |

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 4.1 | Устаревший просмотр: открыть окно подтверждения, а в это время изменить тот же JSON другим клиентом и нажать «Применить» | Сообщение «Содержимое изменилось с момента просмотра. Если веб-панель не поднята, шаг получает `SKIPPED (нужен второй клиент)`; гонка закрыта автотестом `TestConfirmRaceWithConcurrentEdit` (файл A02) | |

## Часть 5. Опасные ключи

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 5.1 | В «Custom config JSON» вставьте `{"inbounds": [{"type": "mixed", "tag": "extra-in", "listen": "0.0.0.0", "listen_port": 12345}]}` и сохраните | В окне подтверждения предупреждение «Custom-поля меняют входящие подключения (inbounds): это может открыть порт в сети или сломать прокси и TUN.»; в «Затронутых ключах» есть `inbounds` | |
| 5.2 | Нажмите «Отмена» | Не подтверждено; бейдж «custom: не подтверждено» остаётся | |
| 5.3 | Очистите поле «Custom config JSON» (оставьте пустым) и сохраните | Бейдж исчез: нет custom-содержимого | |
| 5.4 | Тип «Свой JSON» → «JSON полного конфига» (если доступен в списке типов: «Свой JSON», «Цепочка»): вставьте любой объект | Для такого профиля предупреждение «Конфиг профиля заменяется целиком: остальные настройки LAVRay для него не действуют.» | |

## Часть 6. Неподтверждённый JSON не применяется к подключению (необязательно, нужен рабочий сервер)

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 6.1 | Выключите переключатель «Системный прокси» (чтобы не менять систему). У рабочего сервера задайте «Custom outbound JSON» `{"connect_timeout": "7s"}`, сохраните, в окне нажмите «Отмена» | Бейдж «custom: не подтверждено» | |
| 6.2 | Подключитесь к этому серверу | Подключение проходит как обычно (свой JSON не применяется, пока не подтверждён); трафик идёт | |
| 6.3 | Для сервера типа «Свой JSON»/«JSON полного конфига» без подтверждения | Подключение **не** выполняется (профиль «свой полный конфиг» не подключается до подтверждения; заметки 0.3.0) | |
| 6.4 | Подтвердите, подключитесь | Подключается | |

## Критерии PASS/FAIL

| № | Критерий | Шаги |
|---|---|---|
| К1 | Некорректный JSON отвергается с позицией ошибки; не объект и размер > 256 КиБ отвергаются | 1.3–1.5 |
| К2 | Окно подтверждения: diff, затронутые ключи, галочка и «Применить»; без галочки «Применить» недоступна | 2.1–2.6 |
| К3 | Esc закрывает окно без подтверждения, фокус возвращается; ловушка фокуса | 2.4, 2.8 |
| К4 | Переименование и правка пробелов подтверждение сохраняют | 3.1–3.2 |
| К5 | Правка содержимого, включая возврат A→B→A, подтверждение снимает | 3.3–3.4 |
| К6 | `inbounds` даёт предупреждение; отказ оставляет бейдж | 5.1–5.2 |
| К7 | Неподтверждённый JSON не применяется (свой полный конфиг не подключается) | 6.2–6.3 |

## Что собрать

Скриншоты: поля с ошибками, окно подтверждения (diff, ключи, предупреждение), бейдж. Тексты ошибок.

## Откат / уборка

Удалите сервер `m05-test` («Серверы» → меню строки → «Удалить»). Верните переключатель «Системный прокси» во включённое состояние, если выключали.

`results/M05.md` по `templates/REPORT.md`; шаги — номера таблиц. Провал К7 или подтверждение, выставленное без действий пользователя, — `critical`; К4, К5 — `major`; прочие — `minor`.
