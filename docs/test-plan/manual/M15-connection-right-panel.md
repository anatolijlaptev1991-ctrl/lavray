# M15. Правая панель «Подключение»: внешний IP через туннель, удалённый DNS, нет строки «Потери» (хвосты B)

| Поле | Значение |
|---|---|
| ID | M15 |
| Слой | ручной (человек или агент с computer-use по снимкам экрана; PowerShell нужен для сверки IP) |
| Время | 25–35 минут (+5 минут ожидания в необязательном шаге 3.5) |
| Зависимости | M01, M03 (рабочий сервер, второй рабочий сервер желателен), M04 (экран «Соединения»). Автоматика: A05 (`ConnRight.test`, `ConnRightRows.test`); внешний IP зависит от сети и по API в плане не проверяется |
| Опасность | **прокси**: подключение в режиме системного прокси (M03); после проверки отключитесь |

## Цель

Проверить карточку «Качество связи» в правой панели экрана «Подключение»: внешний IP определяется **через туннель** после подключения, держится в кэше 5 минут и привязан к сеансу, кнопка «Обновить внешний IP» спрашивает заново; ошибка показывается рядом и не прячет кнопку; строка «Удалённый DNS» показывает DNS активного набора правил и меняется вместе с набором; строки «Потери пакетов» больше нет ни в одном языке.

## Предусловия

- **Тестовый ПК подтверждён.** Первая команда файла: `. C:\lavray-test\env.ps1; Test-TestPc` должна напечатать `True` (маркер `C:\lavray-test\TESTPC_OK` есть, создан на этом ПК, не старше 30 суток; `01-ENVIRONMENT.md`, раздел 3). `False` — итог файла `BLOCKED`, ни одного действия.
- Версия `<TAG>` (по умолчанию `v0.9.1`; на момент написания — `main` на `773b4e8`). Есть рабочий сервер `S1` и по возможности второй рабочий сервер `S2` с другим выходным IP (M02, M03). Сервер-пустышка `socks://127.0.0.1:1#m15-dead` добавлен («Серверы» → «Импорт» → «Ссылка»).
- Прямой IP ПК (без LAVRay) записан: `(Invoke-RestMethod https://api.ipify.org)` при отключённом LAVRay. Если у ПК выходной IP тот же, что у `S1`, шаги сверки получают `BLOCKED` (нечего сравнивать).
- Ширина окна не меньше 1100 пикселей (на узком окне правая панель может не помещаться).

## Часть 1. Состояние без подключения

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 1.1 | «Подключение» при отключённом LAVRay: карточка «Качество связи» | Ячейки: «Задержка», **«Внешний IP (через туннель)»**, **«Удалённый DNS»**, «Проверка», на всю ширину «Пресет маршрутов» | |
| 1.2 | Ячейка «Внешний IP (через туннель)» | Значение «—», рядом кнопка-значок (подсказка «Обновить внешний IP») **неактивна** | |
| 1.3 | Ячейка «Удалённый DNS» | Подпись DNS активного набора, например «Авто» (подписи те же, что на карточках «Правила» → DNS: «Авто», «Через туннель», «DoH», «DoT», «Локальный», «Дополнительно», либо хост своего сервера); пока ядро не ответило — «—» | |
| 1.4 | Поиск строки потерь: в карточке «Качество связи» нет строки «Потери пакетов» | Строки нет. Сделайте то же в English (меню языка, M18): строки «Packet loss» тоже нет | |

## Часть 2. Внешний IP после подключения

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 2.1 | Выберите `S1`, режим «Системный прокси», «Подключиться» | После «Подключено» в ячейке «Внешний IP (через туннель)» появляется адрес (за секунды); кнопка «Обновить внешний IP» активна | |
| 2.2 | Сверка: `curl.exe --proxy http://127.0.0.1:2080 https://api.ipify.org` | Печатает тот же адрес, что показан в панели, и он **отличается** от прямого IP | |
| 2.3 | Не нажимая ничего, подождите 10 секунд | Адрес не меняется, мигания и повторных запросов нет | |
| 2.4 | Нажмите «Обновить внешний IP» | На время запроса кнопка занята (`aria-busy`, индикатор), затем адрес снова показан (тот же, если выход не менялся) | |
| 2.5 | Экран «Диагностика» → «Соединения» (M04) до и после 2.4 | После «Обновить» в списке появляется новое короткое соединение к службе определения адреса (запросы «Обновить» видны, фоновых запросов без нажатия нет) | |

## Часть 3. Кэш на 5 минут и привязка к сеансу

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 3.1 | Перейдите на «Серверы» и вернитесь на «Подключение» (меньше чем через 5 минут после 2.4) | Адрес показан сразу, **без нового запроса** (в «Соединения» новых записей к службе адреса нет) | |
| 3.2 | «Отключить» | Значение «—», кнопка снова неактивна | |
| 3.3 | Подключитесь к `S1` снова | Адрес определяется **заново**: новый сеанс (повторный запуск) сбрасывает кэш; в «Соединения» новая запись к службе адреса | |
| 3.4 | Если есть `S2`: «Отключить», подключитесь к `S2` | Показан выходной IP `S2` (сверка командой 2.2), старый адрес `S1` не остаётся | |
| 3.5 | (необязательно, 5 минут) Оставайтесь подключённым на другом экране более 5 минут, затем откройте «Подключение» | Адрес запрашивается заново (кэш истёк): в «Соединения» новая запись; без возврата на экран запросов нет | |

## Часть 4. Ошибка и повтор

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 4.1 | «Отключить», выберите `m15-dead` (`socks://127.0.0.1:1`), «Подключиться» (M03 2.1 показывает, что ядро поднимается, а связи нет) | Состояние «Подключено» (возможно с предупреждением проверки связи) | |
| 4.2 | Ячейка «Внешний IP (через туннель)» | Адрес **не** показан (остаётся «—»), рядом красный текст ошибки (роль «предупреждение»); кнопка «Обновить внешний IP» **осталась активной** (ошибка не прячет её). Запишите текст ошибки дословно | |
| 4.3 | Нажмите «Обновить внешний IP» | Снова запрос и снова ошибка (повтор возможен); приложение не зависает | |
| 4.4 | «Отключить», подключитесь к `S1` | Адрес определился, текст ошибки исчез (ошибка не «залипает» между сеансами) | |
| 4.5 | Пока адрес показан, отключите интернет на ПК (адаптер Wi-Fi/Ethernet на ВМ) на 20 секунд и нажмите «Обновить внешний IP»; затем верните сеть и нажмите ещё раз | Во время обрыва — ошибка рядом с ячейкой, **прежний адрес из кэша остаётся видимым или «—»** (запишите, что именно); после возврата сети — адрес снова определён | |

## Часть 5. Удалённый DNS активного набора

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 5.1 | «Правила» → вкладка «DNS»: запомните выбранную карточку (например, «Авто») | Подпись в ячейке «Удалённый DNS» совпадает с названием выбранной карточки | |
| 5.2 | Выберите другую карточку (например, «DoH» или «Через туннель»), вернитесь в «Подключение» | Ячейка «Удалённый DNS» показывает новую подпись (она отражает сохранённые настройки набора) | |
| 5.3 | Режим «Дополнительно» (свои серверы) | Подпись «Дополнительно» | |
| 5.4 | Если задан свой удалённый DNS-адрес без выбранной карточки (например, `https://dns.google/dns-query`) | В ячейке только хост: `dns.google` | |
| 5.5 | «Правила» → «Маршрутизация»: активируйте другой набор (M09) и вернитесь | Ячейка «Пресет маршрутов» показывает новое имя; «Удалённый DNS» перечитан для нового набора | |
| 5.6 | Верните исходные карточку DNS и набор | Исходное состояние | |

## Часть 6. Откат

«Отключить»; удалите `m15-dead`; убедитесь, что прокси снят: `(Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings').ProxyEnable` равен исходному (M03, часть 5).

## Отчёт

`results/M15.md` по `templates/REPORT.md`; шаги — номера таблиц. Серьёзность: показанный адрес не совпадает с выходным IP туннеля (прямой IP вместо туннельного) (К2) — `critical` (ложное чувство защиты); кэш не сбрасывается между сеансами или запросы идут без нажатия (К3), ошибка прячет кнопку (К5) — `major`; расхождение подписи со словарём — `minor` или `doc`.
