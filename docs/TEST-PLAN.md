## 2. Бюджеты производительности (CI, отчёт 5.4)

| Метрика | Бюджет | Как мерить |
|---|---|---|
| Холодный старт до первого кадра окна | p50 ≤ 600 мс, p95 ≤ 1 000 мс | метка из Rust при показе окна + `performance.now()` первого кадра; Windows 11, эталонный ноутбук |
| Старт до «готов к подключению» | ≤ 1 500 мс | ядро ответило на health-запрос |
| Память UI (все процессы WebView) в простое | ≤ 120 МБ | private bytes дерева процессов |
| Память ядра с LAV Preset RU, без трафика | ≤ 60 МБ | RSS |
| Память в трее (окно закрыто) | ≤ 70 МБ всего | после уничтожения WebView |
| Установщик Windows | ≤ 25 МБ | размер NSIS |
| CPU в простое (окно видно, подключено) | ≤ 1 % | замер 60 с |

Деградация бюджета блокирует merge. Техники достижения (окно вместо WebView держит трей, скрытое окно до первого кадра, бандл ≤ 250 КБ gzip, виртуализация списков, `opt-level=z`, `-trimpath`, `cache_file`) — отчёт 5.4.

## 3. Критерий выхода из «рекурсии до нуля» (Доктрина)

- Каждое замечание ревью классифицируется по рубрике серьёзности: **critical** (утечка/выполнение кода/потеря данных), **major** (отказ функции, обход защиты), **minor** (локальный дефект), **вкус** (субъективное).
- Не более **3 раундов** ревью на модуль; после третьего раунда remaining minor и «вкусовые» замечания переносятся в issue и не блокируют выход.
- Решение о выходе из рекурсии **подписывает человек** (владелец или назначенный ревьюер); автогейты (наборы 1–8) при этом обязаны быть зелёными.
