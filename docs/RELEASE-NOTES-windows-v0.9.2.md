# LAVRay 0.9.2 для Windows

Выпуск исправляет автозапуск с правами администратора и добавляет автоподключение при запуске: после входа в Windows LAVRay сам поднимает последнее удачное подключение. Кроме того, в нём собраны улучшения быстродействия и надёжности оболочки, ядра и интерфейса.

## Исправлено

- **Автозапуск с правами администратора.** Раньше автозапуск был обычной записью в `HKCU\...\Run`: LAVRay стартовал после входа без повышения прав, и TUN не поднимался. Теперь, если один раз запустить установленный LAVRay от имени администратора, автозапуск сам переходит в задачу планировщика с правами администратора (`Run` удаляется, при входе запускается одна оболочка). В «Настройки → Общие» видно, каким способом включён автозапуск и что делать, если задачу не удалось создать.
  - Портативная версия задачу с повышением не создаёт: автозапуск с правами доступен только установленной копии.
- **Автоподключение при запуске.** Новая настройка «Настройки → Общие → Подключаться автоматически при запуске» (по умолчанию выключена). Если включить её, после запуска LAVRay один раз подключается к последнему удачно подключённому серверу в том же режиме.
  - Попытка одна за запуск оболочки, до трёх подходов с нарастающими паузами, не дольше 30 секунд. Ручное «Отключить» остаётся отключением: автоподключение не следит за соединением и не поднимает его повторно. Если ядро перезапущено после сбоя, само оно не подключается.
  - Если подключиться не удалось, ошибка видна в окне, а системный прокси не остаётся направленным на неработающий локальный адрес.
  - Работает без MCP.
- **TUN после перезапуска от администратора.** Если для TUN не хватило прав, а вы выбрали «Перезапустить от администратора», приложение запоминает намерение и после перезапуска само довершает подключение (одно действие, без повторного запроса UAC).

## Как включить

- Обычный режим: **«Настройки → Общие → Автозапуск с системой»** и **«Подключаться автоматически при запуске»**.
- Для TUN: один раз запустите установленный LAVRay от имени администратора (ПКМ → «Запуск от имени администратора»). Автозапуск перейдёт в задачу планировщика с правами администратора, и TUN будет подниматься сразу после входа без запроса UAC.

## Производительность и надёжность

Изменения внутренние, интерфейс остался прежним. Измеренных в приложении цифр здесь нет: заявлено только то, что проверено тестами.

- **Оболочка, супервизор ядра** (#4): ожидание готовности ядра прерывается командой «Стоп» без лишних перезапусков; остановка ядра ограничена по времени и не зависает; состояние «Остановлено» выставляется только после подтверждения чистоты (прокси, адаптер, процессы); длинная строка из пайпа ядра усекается с пометкой; журнал оболочки в установившемся режиме не выделяет память (проверено тестом).
- **Оболочка, копии и чтение** (#2): меньше лишнего копирования данных (протокол интерфейса, снимок экрана, сохранение файла); небольшие JSON-файлы читаются с ограничением размера; вывод проверки подписи читается сразу, а не после завершения процесса; снимок прокси записывается с синхронизацией на диск; релизная сборка использует `lto=thin`.
- **Ядро** (#3): `GetStatus` читает шесть настроек вместо всех; журнал соблюдает `max_lines_per_second`, не режет символы UTF-8 и не раздувает память от очень длинных строк; сводка трафика с фильтром по профилям читает только названные профили; повторный тест задержки по профилю, который уже проверяется, получает `ALREADY_EXISTS`, а новый пакетный тест заменяет предыдущий вместо ошибки.
- **Интерфейс** (#6): один опрос статуса ядра и один поток Stats на все экраны; в свёрнутом в трей окне статус опрашивается реже; журнал накапливает строки в кольце и обновляет экран не чаще раза в 50 мс; поиск серверов ждёт 200 мс после ввода и отбрасывает устаревшие ответы; таблица «Соединения» не перерисовывает неизменные строки; импорт отклоняет файл больше 16 МиБ до чтения.

## Важно при обновлении

- Установщик ставится поверх 0.9.1, 0.9.0 и 0.3.0: серверы, подписки, настройки и автозапуск сохраняются.
- **Если для 0.9.1 вы вручную создавали внешнюю задачу автоподключения** (скрипт Python, VBS или MCP в «Планировщике заданий» либо в «Автозагрузке»), её нужно удалить: теперь автоподключение встроено, и две задачи могут мешать друг другу.
- Автоподключение по умолчанию выключено; запомненный сервер и режим берутся из последнего удачного подключения.
- Экран «Обновления» пока показывает «Обновления не настроены». Пока ключи подписи не созданы, обновление делается установщиком поверх.

## Файлы

| Файл | Что это |
|---|---|
| `LAVRay-0.9.2-x64-setup.exe` | Установщик: `C:\Program Files\LAVRay`, при установке один раз просит права администратора |
| `LAVRay-0.9.2-portable-x64.zip` | Без установки; автозапуск с правами администратора доступен только установленной версии |
| `SHA256SUMS.txt` | Контрольные суммы Windows-файлов |
| `lavray-core-linux-amd64`, `lavray-core-linux-arm64` | Headless-ядро для Linux со встроенной веб-панелью |
| `ui-dist.tar.gz` | Собранный интерфейс веб-панели (для пакетов OpenWrt) |
| `SHA256SUMS-linux.txt` | Контрольные суммы Linux-файлов |

Сборки не подписаны сертификатом Windows: при первом запуске SmartScreen может предупредить — «Подробнее» → «Выполнить в любом случае». Сверьте `Get-FileHash <файл> -Algorithm SHA256` с `SHA256SUMS.txt`.
