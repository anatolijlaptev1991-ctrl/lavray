> Как использовать: открой Claude Code в корне `D:\ZCode\nekobox` (чтобы он видел все папки ниже), вставь текст целиком.

---

Ты — ведущий независимый аудитор, продуктовый архитектор и «суперконструктор» продуктов. Проект **LAVRay** — полная переработка прокси-клиента NekoBox (форк MatsuriDayo/nekoray, Qt/C++ + Go/sing-box) в новое кроссплатформенное приложение: Windows / Linux (Ubuntu) / macOS / OpenWrt. Твоя задача — **сверхдетальный аудит** (1) плана работ и архитектуры, (2) дизайна интерфейса и (3) свободный конструктив: поиск упущенного и генерация улучшений. Ты консервативен в выводах, дотошен и не принимаешь на веру — проверяй утверждения документов по исходному коду. При этом ты не только критикуешь — ты строишь: каждое замечание сопровождается готовым решением.

## Контекст проекта (зафиксированные решения — не оспаривай сам стек, аудируй исполнение)

- Стек: Go-ядро (форк neko + sing-box 1.14.1-neko.1) сохраняется; Qt-часть переписывается на Rust (Tauri 2); UI — единая кодовая база React+TypeScript в двух режимах: нативное окно приложения и веб-интерфейс (браузер/OpenWrt-панель) — оба обязаны быть безупречны.
- Репозитории: общий `lavray` + `lavray-windows`, `lavray-linux`, `lavray-macos`, `lavray-openwrt`.
- OpenWrt: headless-демон (procd) + веб-панель + luci-app-lavray; стартовые архитектуры x86_64, aarch64_generic.
- i18n: русский, китайский (упрощённый), английский, испанский, немецкий — заложены в дизайн. Темы: тёмная + светлая.
- Встроенный маршрутный пресет «LAV Preset RU» (из nekobox-ru-bypass-games) во все сборки.
- Автообновления: приложения проверяют GitHub Releases своих репо (манифест latest.json + ed25519-подпись + sha256, каналы stable/beta, автоматический откат); обновление ядра sing-box — только через строгий аудит-гейт.
- Лицензия GPL-3.0 обязательна (производная nekoray/sing-box).
- Доктрина качества: всё вне ядра sing-box проходит рекурсивные циклы «аудит → исправление → повторный аудит» до нуля критичных/мажорных замечаний; три уровня: машинный (тесты/линтеры/бенчмарки), adversarial-ревью, визуальный (visual-judge).

## Задача 1 — аудит плана и архитектуры: «то, что нужно сделать»

1.1. **Полнота требований**: сверь REQUIREMENTS.md с реальным кодом (`ui\`, `main\`, `sub\`, `db\`, `fmt\`, `sys\`) — какие функции/настройки/крайние случаи НЕ попали в каталог (файл-источник для каждого пропуска)? Какие из 256 FR стоит осознанно отбросить в LAVRay и почему?
1.2. **Архитектурные риски** разреза Tauri 2 (Rust) + React + Go-ядро как sidecar с HTTP/WS API: жизненный цикл ядра, краш-восстановление, права (TUN), производительность IPC для графика трафика, безопасность localhost-API (токен, CORS, привязка к 127.0.0.1). Что упущено? Перенос ConfigBuilder+парсеров из C++ в Go (~3–6 тыс. строк) — порядок работ, риски регрессий, стратегия golden-тестов паритета конфигов?
1.3. **Платформенная матрица**: слепые зоны Windows (NSIS, системный прокси, UAC для TUN, трей), Ubuntu (.deb/AppImage, GNOME/KDE, portal), macOS (notarization, сетевые расширения, приватность), OpenWrt (разнообразие target'ов, память роутеров, procd, luci). Что нереалистично или упущено?
1.4. **UPDATE-SYSTEM.md**: найди дыры — атаки на канал обновлений (компрометация релизов, DNS, откатные атаки, key rotation), целостность OpenWrt-пути, недоступность GitHub (гео-блокировки РФ/КНР — критично для аудитории!), атомарность и откат AppImage/.deb. Сверь с дырами текущего апдейтера из BUGS.md — все ли закрыты?
1.5. **План тестирования**: достаточно ли покрытия для Доктрины (unit/контрактные/интеграционные/E2E/визуальные/фаззинг/бенчмарки с бюджетами/стресс)? Что добавить (миграция конфигов NekoBox→LAVRay, тесты 5 локалей, контрасты в CI, тайминги запуска)?
1.6. **Пропущенные работы**: перечисли всё, что придётся сделать, но чего нет в документах (иконки/логотип под платформы, crash-репорты, migration wizard, крэш-безопасность конфигов, deep-links lavray://, деинсталляция, телеметрия-опциональность...).

## Задача 2 — сверхдетальный аудит интерфейса: «как улучшить»

Пройди прототип по всем экранам (Подключение, Профили, Редактор профиля, Подписки, Маршрутизация, DNS, Журнал, Настройки, Центр обновлений, Онбординг) в каждом языке × теме × режиме и оцени:
2.1. Отклонения от токенов DESIGN-SYSTEM.md (цвета, отступы, радиусы, типографика) — по экранам.
2.2. Какие MUST-требования из REQUIREMENTS.md не отражены/неочевидны в прототипе.
2.3. i18n-качество всех 5 языков: обрезки/переполнения, кальки, форматы чисел/дат/скоростей, +40% запас для DE/ES, естественность упрощённого китайского.
2.4. Информационная архитектура: где пользователь потеряется; клики до частых действий; empty/error/loading-состояния.
2.5. «Нативность» и корректность веб-деградации: титл-бар, меню, хоткеи, фокус-кольца, drag&drop, reduced-motion; чтобы не ощущалось «сайтом в рамке».
2.6. Доступность: контрасты по токенам, клавиатура, aria, размеры целей.
2.7. Визуальный craft: плотность, выравнивание, иерархия, hover/focus — что выглядит дёшево, конкретно.
