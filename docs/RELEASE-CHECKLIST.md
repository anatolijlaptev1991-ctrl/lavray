Проработка «пункта 5» вопросов владельца (решение 2026-10-23: «сам проработай»). Документ живой: отмечай `[x]`. Связанные: `LICENSES.md` §2, `SECURITY.md`, `UPDATE-SYSTEM.md` v2.0, `PLATFORM-MATRIX.md` §2.

## 1. Порядок публичности репозиториев

**Рекомендация: два шага.**

1. **Шаг 1 — главный `lavray`** (исходники ядра/оболочки/UI, docs, пресеты): публичным первым, когда собирается и проходит CI. Пустых артефактов не требует, даёт раннюю видимость и вклад.
2. **Шаг 2 — 4 платформенных** (`lavray-windows/linux/macos/openwrt`): публичными **вместе с первыми готовыми бинарными релизами** (чтобы репозитории не висели пустыми), не позже чем через 2–4 недели после шага 1.

Альтернатива «все сразу» допустима, но оставляет 4 репо без релизов — хуже для первых пользователей.

До публичности: проход по всему дереву — нет ли случайно закоммиченных ключей/токенов (`gitleaks` в CI уже стоит — убедиться, что он в required checks).

## 2. Защита веток (при переводе в публичный режим; на бесплатном плане для приватных недоступно)

Для каждого из 5 репо, ветка `main`:

```bash
gh api -X POST repos/anatolijlaptev1991-ctrl/<repo>/rulesets -f name='main-protection' \
  -F target=branch -F 'conditions[ref_name][includes][]=refs/heads/main' \
  -F 'rules[][type]=required_status_checks' -F 'rules[][parameters][strict]=true' \
  -f 'rules[][parameters][check_contexts][]=CI' \
  -F 'rules[][type]=pull_request' -F 'rules[][parameters][required_approving_review_count]=1' \
  -F 'rules[][type]=no_force_pushes' -F 'rules[][type]=delete_allowance'
```

(Или через UI: Settings → Rules → Rulesets.) Смысл: прямой push в main закрыт (работа через PR + зелёный CI), force-push и удаление запрещены.CODEOWNERS — после появления второго контрибьютора.

## 3. Имя и товарный знак

- **Web-поиск 2026-10-23 (сделан):** «LAVRay» как бренд/продукт/торговая марка **не встречается** — только фамилия Lavray (Helene Lavray, Dow, LinkedIn) и бытовые упоминания. Конфликтов нет.
- Формальная проверка баз USPTO / EUIPO / WIPO / Роспатент / CNIPA — опционально юристу; для open source-проекта без регистрации марки некритично, становится важно при сайте/донатах/магазинах.
- Домены: решить, нужен ли сайт (для SECURITY.md — публикация отпечатков минимум по двум каналам, один вне GitHub). Минимум без сайта: GitHub Releases + codeberg-зеркало + Telegram.

## 4. Неподписанные сборки (решение владельца 2026-10-23: v1 без кодоподписи)

Обязательный раздел «Установка и проверка» в README каждого платформенного репо:

- **Windows:** SmartScreen покажет «Система защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае».
- **macOS:** Gatekeeper заблокирует неизвестного разработчика → Системные настройки → Конфиденциальность и безопасность → «Открыть всё равно»; либо в Терминале: `xattr -cr /Applications/LAVRay.app`.
- **Проверка подлинности (обязательна к указанию):** minisign-подписи и sha256 всех артефактов из манифеста TUF-lite; отпечаток root — в README и RELEASES. Формула: `minisign -Vm LAVRay-*.exe -P <root-pubkey>`.
- Встроенный авто-обновлятор проверяет подписи сам — пользователь ничего не делает при обновлениях.
- Вернуться к теме кодоподписи (SignPath Foundation для open source — проверить допуск VPN-инструментов; или партнёр за рубежом) — после первого релиза, отдельной задачей.
