## Как проводился аудит

1. **Документы** прочитаны целиком; утверждения сверены с кодом.
2. **Код форка** проверен пятью параллельными проходами: UI и системная интеграция (`ui/`, `main/`, `sys/`, `3rdparty/`); данные и ядро (`db/`, `fmt/`, `sub/`, `go/`, `rpc/`, подсчёт строк порта); безопасность (верификация всех 24 LNB, новые находки, модель угроз обновлений); конкуренты (11 продуктов, источники на 23.10.2026); локализация (выгрузка словарей, замер вёрстки в браузере).

Контраст всех токенов посчитан по формуле WCAG 2.x. 9 скриншотов прототипа просмотрены вручную.
4. **Бренд и движение** — сделан интерактивный стенд и экспорт SVG (раздел 5.8).

## 1. Резюме: 73 главные проблемы

Формат: **область → проблема → влияние**. Группы упорядочены по влиянию на успех, внутри групп — по серьёзности. Подробности и инструкции — в разделах 2–5.

### Безопасность
1. Импорт → `nekoray://` в подписке несёт `c_cfg`, `MergeJson` вливает его без фильтра, `external_ui_download_url` распаковывает zip без защиты от `..` → полудоверенный провайдер подписки может записать файл в автозагрузку пользователя (цепочка до RCE).
2. API ядра → планируются `Start(core_config)` с сырым JSON sing-box и `Test(address, url)` → запись файлов и SSRF при любом обходе авторизации; на OpenWrt ядро работает от root.
3. Десктоп → открытый HTTP/WS на 127.0.0.1 → любая веб-страница управляет туннелем (CSRF, DNS-rebinding, перебор портов).
4. Права → для TUN от root/админа запускается скрипт или конфиг из каталога пользователя, либо весь GUI → локальное повышение привилегий.
5. Веб-панель OpenWrt → `0.0.0.0`, статичный токен, TLS «опционально», нет логина → открытая админка шлюза в LAN и гостевых сетях.
6. Локальный прокси → SOCKS на loopback без авторизации (класс уязвимостей апреля 2026) → любое приложение узнаёт выходной IP и обходит раздельную маршрутизацию.
7. Логи → секреты подписок, env и argv внешних ядер, `core_config` при `-debug`, результат QR → утечки в баг-репортах и в веб-панели.
8. Сеть → «Разрешить LAN» слушает `::` без обязательного пароля → открытый прокси в локальной сети.
9. Сборка → Qt без хеша, actions по тегам, сторонний `ghr` с токеном, короткий SHA зависимостей → закладка попадает в релиз.

### Дистрибуция и обновления
10. Манифест → подписан только артефакт → freeze, откат на старую уязвимую версию, `mandatory` как DoS, beta вместо stable.
11. Ключи → один ключ без ротации и отзыва, обычно в секретах CI → кража ключа = подписанный вредоносный апдейт всем.
12. Доступность → пиннинг на github.com, зеркал нет, «нет обновлений» при блокировке → аудитория РФ и КНР молча остаётся без обновлений.
13. Откат → его исполняет новая, возможно неработающая версия; Tauri прошлую версию не хранит → принцип «откат всегда возможен» невыполним.
14. Пресеты и geo → без подписи → подмена rule-set тихо уводит трафик мимо туннеля.
15. OpenWrt → 25.12 перешёл на apk, все документы про opkg/ipk → пакет не ставится на актуальную стабильную ветку.
16. Подпись кода → плана нет, сертификаты из РФ труднодоступны → SmartScreen, Gatekeeper и антивирусы отпугивают пользователей.
17. Linux → Tauri updater умеет только AppImage, TUN в AppImage невозможен, apt-репозиторий без `signed-by`/`Valid-Until` → две несовместимые модели прав и обновлений.
18. Аккаунт → репозитории, Pages, Actions и ключи под одним аккаунтом GitHub → единая точка отказа.

### Архитектура
19. Транспорт UI → `ui/README` описывает прямой HTTP, `shell/README` — шлюз IPC → токен в JS, любой XSS даёт полный контроль.
20. Привилегии → нет минимального помощника (служба Windows, systemd, SMAppService) → UAC на каждый запуск TUN или LPE.
21. Данные → состояние переезжает в ядро без модели конкурентности; хранилище — сотни JSON с неатомарной записью → гонки и порча настроек (U-10).
22. Надёжность → паники (happ, `getBetweenStr`, nil config) роняют сайдкар, recover нет → разрыв туннеля.
23. Крах → нет зачистки TUN, маршрутов и системного прокси при следующем старте → «нет интернета после падения».
24. Порт билдера → реально 4,4 тыс. строк C++ (5–7 тыс. Go без тестов), без oracle, импортёра и санитайзера в оценке → сроки «4–8 недель» нереальны.
25. Порт билдера → паритет закрепит дефекты (hy2 `hop_ports` вместо `server_ports`, нет `cache_file`, мёртвые поля маршрутизации) → отказ старта без сети и неработающий port hopping.
26. Протоколы → штатный sing-box не умеет XHTTP, а план отказывается от внешних ядер → часть российских подписок 2026 года не работает.
27. Подписки → пустой или мусорный ответ 200 удаляет все профили группы → массовая потеря серверов там, где провайдеры отдают заглушки.
28. Статистика и логи → один потребитель (`Reset`), троттлинг на стороне GUI → не масштабируется на окно + веб-панель.

### Платформы
29. OpenWrt → `aarch64_generic` не покрывает Filogic (`cortex-a53`) и Raspberry Pi 4 (`cortex-a72`) → самые массовые роутеры вне поддержки.
30. OpenWrt → режим шлюза не спроектирован (nftables/TProxy, dnsmasq, устройства LAN, watchdog) → получается «прокси на порту», а не шлюз.
31. OpenWrt → требования к RAM и flash не заданы (ядро 30–60 МБ, бинарь 30+ МБ, износ flash) → не работает на массовых устройствах.
32. macOS → без Developer ID в macOS 15 запуск только через настройки безопасности, App Translocation ломает самообновление → массовая установка не проходит.
33. macOS → TUN и системный прокси требуют root, ветки повышения нет → TUN недоступен.
34. Linux → в «чистом» GNOME нет трея, WebKitGTK даёт пустые окна на NVIDIA/Wayland → «окно потерялось», плохие отзывы.
35. Windows → WebView2 бывает не установлен; кастомный заголовок теряет Snap Layouts → проблемы установки и «сайт в рамке».
36. Нативность → в прототипе нет переключателя ОС, кнопки окна Windows слева, нет меню macOS «Правка» → требование ТЗ 2.5 нельзя проверить.

### UX/UI и доступность
37. Главный экран → текущий сервер обрезан до «Hy T…» во всех языках → нет ответа на вопрос «через что я подключён».
38. Онбординг → настраивает язык и тему, но не добавляет сервер и не выбирает режим → провал первого запуска.
39. Диагностика → нет проверки маршрута и помощника «почему не работает» → неэксперты уходят, поддержка перегружена.
40. IA → «Профили» и «Подписки» раздельно, DNS отдельно от маршрутизации → пользователь теряется между семью разделами.
41. Состояния → пустые, ошибочные и загрузочные состояния не нарисованы ни на одном экране → прототип неполон.
42. Покрытие → в прототипе нет цепочек, групп, настроек TUN, авторизации входящего прокси, соединений, полного теста, бэкапа → риск переделки дизайна.
43. Профили → строка 69 px, фильтр по протоколу, нет группировки по подписке и плотности, нет маркера активного → список не работает на 300+ серверах.
44. Обновления → «Откатиться» на текущую версию, нет «Проверить сейчас», не видно размера, подписи и последствий → недоверие к обновлениям.
45. Режим → выбор «системный прокси / TUN» спрятан в статус-бар → игры и CLI идут мимо прокси, пользователь не понимает почему.
46. Пресеты → один региональный пресет RU на пять языков → для китайской аудитории дефолт бесполезен.
47. Доступность → `text.tertiary` 2,58–3,49:1 и статусные цвета светлой темы 3,44–4,41:1 на всех экранах → нарушение WCAG AA и собственной DS.
48. Доступность → диалоги без ловушки и возврата фокуса и без имени, закрытая панель ловит Tab, меню «⋯» без клавиатуры → функции недоступны без мыши.
49. Доступность → веб-панель с минимальной шириной 960 px → на телефоне не работает.
50. Доступность → дорожка выключенного переключателя и границы полей 1,24–1,32:1, цели 22–28 px → элементы плохо видны, в них трудно попасть.
51. Доступность → нет `forced-colors`, состояние часто передаётся только цветом → пользователи режима высокой контрастности и дальтоники не видят статусов.
52. Бренд → знак читается как иконка терминала и совпадает с иконкой «Журнал» → противоречит позиционированию «приборная панель, а не хакерский тул».

### i18n

3. **Парсеры** (ссылки, base64 в строгом Qt-режиме, Clash YAML, happ) — сразу с фаззингом.

### 3.14 MUST-требования, которых нет в прототипе (п. 2.2)

Проверено поиском по ключам словаря прототипа и визуально. Нет ни экрана, ни элемента для:

- **Цепочки прокси** (Chain, front/landing proxy; REQUIREMENTS §3–4).
- **Управления группами**: создание, перенос профилей, архив (REQUIREMENTS §4). В прототипе группы есть только как подписи в редакторе.
- **Настроек TUN**: стек, MTU, strict route, исключения процессов и адресов (REQUIREMENTS §9).
- **Авторизации входящего прокси** (inbound auth) и прослушивания LAN с паролем.
- **Полного теста** (UDP, скорость загрузки) — есть только задержка.
- **Списка соединений** (FR-UI-213). В форке это заглушка, но для LAVRay это главный инструмент диагностики, и у ядра есть трекер соединений.
- **Экспорта конфигурации ядра** для экспертов и открытия панели Clash API (FR-UI-060).
- **Резервной копии и восстановления** настроек.
- **IPv6** и стратегии разрешения доменов.
- **Kill switch** — блокировки трафика при падении туннеля. В NekoBox её нет, но у конкурентов это стандарт.

### 3.15 Информационная архитектура (п. 2.4)

- **Клики до частых действий** (измерено по прототипу): подключиться — 1; сменить сервер — 2–3, через крошечный чип или через «Профили» → строка → «Подключиться» в панели; добавить подписку — 3, «Профили» → «Импорт» → вставка → «Импортировать». Отдельный раздел «Подписки» при этом не участвует в добавлении. Проверить, куда идёт сайт — невозможно. Сменить режим TUN — неочевидно (пилюля в статус-баре).
- **Где пользователь потеряется:** подписки и профили — два раздела для одной сущности («мои серверы»). DNS отделён от маршрутизации, хотя пресет управляет обоими. Центр обновлений спрятан в карточку внизу сайдбара.
- **Пустые, ошибочные и загрузочные состояния не нарисованы** ни на одном экране: 0 профилей, 0 подписок, ядро не запустилось, нет сети, подписка вернула 0 серверов, тест задержки идёт (прогресс), долгий импорт. DS §6 объявляет `EmptyState`, но его нет.
- Рекомендация (подробнее в 5.7, предложение 2): 5 разделов вместо 7 + Настройки. Подключение · Серверы (профили и подписки вместе, группировка по подписке) · Правила (маршрутизация, DNS, проверка маршрута) · Диагностика (журнал, соединения, утечки, «почему не работает») · Настройки. Обновления — в Настройках и бейджем в сайдбаре.

### 3.16 «Нативность» и веб-деградация (п. 2.5)

- **Меню.** На macOS глобальная строка меню обязательна: «LAVRay → О программе, Настройки ⌘,, Скрыть, Выйти ⌘Q» и меню «Правка». Без пунктов «Правка» в WKWebView не работают ⌘C/⌘V в полях ввода [проверь на Tauri 2, при собственном меню это известная ловушка]. В Windows 11 строка меню «Файл/Вид/Справка» выглядит архаично: лучше меню в кнопке «⋯» или по Alt.
- **Хоткеи.** DS §10 смешивает внутренние сочетания (Ctrl+K, Ctrl+D) и глобальные. Глобальный Ctrl+K отнимет сочетание у всех программ. Нужно разделить: внутренние с Ctrl/⌘ по платформе; глобальные — выключены по умолчанию, назначает пользователь. На Wayland глобальные хоткеи требуют портала GlobalShortcuts и работают не везде.
- **Шрифты.** Inter везде даёт ощущение «сайта в рамке». В режиме приложения — системный шрифт ОС (Segoe UI Variable, SF Pro, Cantarell/Noto), Inter — в веб-режиме и для крупных цифр.
- **Перетаскивание файла** подписки в окно, системный диалог файлов, ссылки в системном браузере, уведомления ОС заявлены в DS §10, но в прототипе не показаны (нет состояния «перетащите сюда»).
- **Reduced motion** учтён глобальным правилом CSS (prototype.html:708). JS-анимации при нём тоже не тикают — проверено, 0 вызовов `requestAnimationFrame` в секунду. Хорошо.
- **Режим высокой контрастности Windows** (`forced-colors`) не учтён вовсе. Фокус-кольца, переключатели и бейджи в нём пропадут.

### 3.17 Визуальный craft (п. 2.7)

- Главный экран при 1280×800 выглядит недоделанным: обрезанные чип и подписи, «сломанный» пустой график, пустая нижняя треть. Это первое, что увидит человек.
- Иерархия Профилей сильная (имя, бейджи, адрес, задержка), но строки слишком воздушные для объёмов подписок.
- Цветовые бейджи протоколов (VLESS янтарный, VMess фиолетовый, Trojan розовый…) — семь цветов без смысла. Это декоративный шум и спор с запретом «фиолетового» из v1.1. Достаточно нейтрального бейджа; цвет оставить статусам.
- Иконки секций Настроек и заголовков карточек окрашены в акцент. Акцент размывается: он должен значить «действие» и «активное».
- Хорошо: тёмная палитра v1.1 спокойная и профессиональная; кнопка «Подключиться» читается; диалоги аккуратные; reduced motion.

**Паритет: без этого LAVRay теряет пользователей** (S — дни, M — 1–3 недели, L — больше месяца):

1. **Импорт** подписок: base64-ссылки, sing-box JSON, Clash YAML, v2rayN; буфер, QR с экрана и из файла; deep links `sing-box://import-remote-profile`, `clash://install-config`, `happ://add`, `hiddify://` — всё с подтверждением. **M–L**
2. **Заголовки подписки**: `subscription-userinfo` (+`x-*-meta-*`), `profile-update-interval`, `profile-title` (`base64:`), `content-disposition`, `profile-web-page-url`, `support-url`, `announce`, `routing`, `#key: value` в теле; полоса трафика и срока, уведомления. **S–M**
3. **Настройки на подписку**: UA (пресеты + свой), свои заголовки, HTTP Basic, обновление через прокси или напрямую, «последний рабочий» при сбое, автотест и фильтр после обновления. **M**
4. **Свой User-Agent и согласование формата**: Marzban отдаёт sing-box JSON только на UA с префиксами SFA/SFI/SFM/SFT/Karing/HiddifyNext. Нужны свой UA, PR в Marzban/Remnawave/PasarGuard и автопроба `/{token}/sing-box`. **S–M**
5. **Совместимость с Remnawave/Happ**: HWID-заголовки (`x-hwid`, `x-device-os`, `x-ver-os`, `x-device-model`) — только по согласию; показ `announce` и `x-hwid-max-devices-reached`. **S**
6. **Режимы** Global/Rule/Direct; системный прокси, TUN и смешанный режим одним кликом; автоочистка прокси и DNS после краша. **M**
7. **Пресеты RU/CN/IR** с автообновляемыми rule-set (runetfreedom: `ru-blocked`, `ru-available-only-inside`, `ru-whitelist`; MetaCubeX; Loyalsoldier) и выбором источника и зеркала. **M**
8. **Редактор правил** (домен, regex, CIDR, geoip, порт, процесс, путь), rule-set по URL, перетаскивание, выбор приложения из списка. **M**
9. **XHTTP**. Штатный sing-box не умеет транспорт XHTTP, который в 2026 году массово используют российские провайдеры. Конкуренты держат Xray как дополнительное ядро (v2rayN, Throne, NyameBox) или форк sing-box-extended. **L** — стратегическое решение (см. ниже).
10. **Протоколы**: VLESS Reality/Vision/ECH, Hysteria2 с hopping, TUIC, AnyTLS, ShadowTLS, WireGuard/AmneziaWG, SS-2022, Naive, Mieru; MASQUE в планах; закрепление сертификата вместо `allowInsecure`. **M–L**

12. **Kill switch и защита от DNS-утечек**, strict route. **M**
13. **Headless, CLI, API** для OpenWrt. **M**
14. **Трей, хоткеи, автозапуск, portable**, резервная копия и WebDAV, импорт из NekoBox и Throne. **S–M**
15. **Подписанные сборки** (Authenticode, notarization), интерфейс минимум на ru/zh/en. **M**

**Уроки чужих провалов:**

1. **Привилегированные службы — главный источник CVE.** Clash Verge Rev: CVE-2025-50505 (неаутентифицированный HTTP-маршрут запускает произвольный бинарь) и CVE-2026-26422 (IPC открыт любому локальному пользователю [проверь]). Clash Party: LPE #706 и RCE через rule-providers. Вывод: IPC с аутентификацией, никаких путей и команд от клиента, подписка — недоверенный ввод.
2. **Loopback-уязвимость (апрель 2026).** Клиенты на Xray и sing-box держат SOCKS5 на localhost без авторизации: любое приложение узнаёт выходной IP и обходит раздельную маршрутизацию; авторизация SOCKS не защищает UDP. У Happ ещё и открытый Xray `HandlerService`.
3. **Детект VPN российскими сервисами (апрель 2026).** По сообщениям СМИ, крупные сервисы должны ограничивать пользователей VPN по репутации IP/ASN, а затем проверками на устройстве (системный прокси, порты, имена tun/wg/utun, MTU) [подлинность методички не подтверждена]. Значит, «RU напрямую» обязателен по умолчанию, имя адаптера и порты должны настраиваться.
4. **Телеметрия разрушает доверие**: Sentry и push-token в Happ при заявлении «не собираем данные»; Firebase в FlClash до 0.9.1; реклама в README и на главных экранах.
5. **Обновления**: отсутствие проверки digest (v2rayN, по репорту), залипшие зеркала (Verge Rev до 2.5.8), антивирусные срабатывания на апдейтер (Throne). Деградация GitHub в РФ: доля отказов выросла с 6 % до 16 % (апрель → май 2026, OONI) [проверь].
6. **Сторы**: Apple убрал Happ из российского App Store (март и июнь 2026), РКН потребовал от Google удалить 233 приложения. Для десктопа — сайт, WinGet/Scoop, apt/rpm, свои зеркала.
7. **Риск мейнтейнера**: nekoray в архиве. Нужны владение организацией, ключи подписи у нескольких людей, зеркало вне GitHub.
8. **Лицензии**: Hiddify — GPLv3 с запретом коммерческого использования (код не заимствовать); Karing и sing-box-extended запрещают использовать своё имя; у upstream sing-box такой пункт тоже есть (5.5).
9. **Crash-safety**: Verge Rev оставлял системный прокси на мёртвом порту (2.5.6) и DNS 114.114.114.114 (2.5.8); у Throne force-quit оставляет прокси. «Страж» восстановления после краша — обязательная часть v1.0.

**Стратегическое решение по XHTTP (P1).** Решение «только sing-box, внешние ядра отбросить» (раздел 2.1) сталкивается с рынком: значимая часть российских провайдеров в 2026 году отдаёт VLESS XHTTP. Варианты: (а) добавить XHTTP в собственный форк ядра (neko-слой уже есть) — дороже, но цельно; (б) поддержать Xray как необязательное дополнительное ядро только для XHTTP-профилей; (в) явно не поддерживать и честно показывать «профиль не поддерживается». Решить до заморозки требований v1.0.

### 5.4 План производительности и лёгкости

Цели из ТЗ («старт < 1 с, память < 100 МБ, бинарь < 25 МБ») нужно сначала сформулировать измеримо: «память» WebView2 — это 4–6 процессов, а ядро с rule-set само занимает 30–60 МБ. Предлагаемые бюджеты для CI:

| Метрика | Бюджет | Как мерить |
|---|---|---|
| Холодный старт до первого кадра окна | p50 ≤ 600 мс, p95 ≤ 1 000 мс | Метка из Rust при показе окна и `performance.now()` первого кадра, Windows 11 на эталонном ноутбуке |
| Старт до «готов к подключению» | ≤ 1 500 мс | Ядро ответило на health-запрос |
| Память UI (все процессы WebView) в простое | ≤ 120 МБ | Private bytes дерева процессов |
| Память ядра с LAV Preset RU, без трафика | ≤ 60 МБ | RSS |
| Память в трее (окно закрыто) | ≤ 70 МБ всего | После уничтожения WebView |
| Установщик Windows | ≤ 25 МБ | Размер NSIS |
| CPU в простое, окно видно, подключено | ≤ 1 % | 60 с замера |

Техники:

- **Окно, а не WebView, держит трей.** При сворачивании в трей уничтожать окно WebView и пересоздавать при открытии (~300 мс). Это главный выигрыш по памяти: в трее работают только Rust-оболочка и ядро.
- **Без белой вспышки**: окно создаётся скрытым с фоном темы (`backgroundColor` в конфиге окна) и показывается после первого кадра; критический CSS инлайнится.
- **Бандл UI**: React 19 + свои компоненты на токенах, без UI-китов и без framer-motion; маршруты разделены на чанки; иконки — только используемые SVG; цель ≤ 250 КБ gzip на первый экран. Списки (профили, журнал, соединения) виртуализированы.
- **Данные потоком, а не опросом**: Tauri Channels; статистика 1 Гц с интерполяцией на клиенте; журнал пачками по 10 Гц с кольцевым буфером в ядре; без перерисовки при скрытом окне.
- **Rust**: `opt-level="z"` или `"s"`, `lto = true`, `codegen-units = 1`, `panic = "abort"`, `strip = true`; минимум плагинов Tauri.
- **Go**: `-trimpath -ldflags="-s -w"`, минимальные build-теги sing-box (только используемые протоколы), без UPX (ложные срабатывания антивирусов). `GOMEMLIMIT` и `GOGC` под профиль устройства; на OpenWrt — отдельная «лёгкая» сборка.
- **Rule-set**: только бинарные `.srs`, `cache_file` включён, встроенные наборы для пресетов — старт без сети.
- **Старт параллельно**: ядро поднимается одновременно с окном; UI сразу показывает последнее известное состояние из снимка, а «Ядро запускается» — только если старт дольше 300 мс.
- **Linux**: без `backdrop-filter` и blur; флаг обхода DMABUF для NVIDIA.

### 5.7 Если бы я был владельцем продукта: три принципиальных предложения

**1. Закрыть сетевую поверхность десктопа и разделить права.** В режиме приложения не открывать никакого TCP-API: UI ↔ Rust через IPC Tauri, Rust ↔ ядро через unix-socket или named pipe с проверкой владельца. HTTP — только в веб-режиме, с логином, проверкой Host и Origin. Права администратора получает только маленький помощник (служба Windows, systemd-unit, SMAppService), который принимает валидированный конфиг и поднимает TUN; парсеры подписок и UI работают без прав. API принимает сущности, а не сырой JSON sing-box. *Почему:* так закрывается сразу целый класс P0 (CSRF и DNS-rebinding к localhost, подписка → RCE, LPE через подмену файлов), и это дешевле, чем латать каждый вектор по отдельности.

**2. Строить интерфейс вокруг задач, а не вокруг сущностей ядра.** Пять разделов вместо семи: Подключение · Серверы (профили и подписки вместе, группировка по подписке) · Правила (маршрутизация, DNS, проверка маршрута) · Диагностика (журнал, соединения, утечки, «Почему не работает?») · Настройки. Онбординг ведёт к подключению: язык по ОС → вставить ссылку или перенести из NekoBox → региональный пресет → «Подключиться». В режиме приложения — системный шрифт ОС, в веб-режиме — адаптивная вёрстка с нижней навигацией. Доступность (контраст, клавиатура, диктор, forced-colors) — критерий приёмки каждого экрана. *Почему:* аудитория — не эксперты, а главная метрика — время до первого подключения; текущая IA повторяет внутреннюю структуру NekoBox.

**3. Сделать доставку обновлений устойчивой к блокировкам и компрометации до первого релиза.** TUF-lite (офлайн root, `timestamp` со сроком, монотонный `serial`), подписанные пресеты и geo, подписанный список зеркал, загрузка через туннель, честный статус «последняя успешная проверка N дней назад», откат силами старой версии, план подписи кода. *Почему:* исправить канал обновлений после выпуска нельзя: старые клиенты будут доверять старому механизму вечно. Для аудитории РФ и КНР недоступный GitHub означает, что без этого обновления просто не дойдут.

### 5.8 Бренд и движение (по особой просьбе)

Стенд со всеми образцами: **`design/concepts/brand-motion.html`** (опубликован как приватный артефакт: https://claude.ai/artifact/5VryMadXgTfsLGQ9g34LLw). Готовые SVG: `design/concepts/logo/` — знак на тёмном и светлом, плитки Windows/Linux и macOS (сетка Big Sur), Linux symbolic, трей Windows (тёмный и светлый) и macOS template в четырёх состояниях.

**Знак.** Текущий глиф почти совпадает с иконкой Lucide `square-terminal` и с иконкой «Журнал» в собственном сайдбаре, а в трее 16 px превращается в шум. Предложены три направления:

- **A «Отражение» (рекомендую).** Буква L — это путь луча, отражённого зеркалом под 45°: луч приходит сверху, отражается и уходит вправо, в конце точка-фотон. Смысл продукта (трафик перенаправляется туда, куда велят правила) и буква названия в одном жесте. В 16 px читается силуэтом (L + точка). Состояния выражаются формой, а не только цветом: нет фотона — отключено, кольцо — подключение, фотон — подключено, разрыв луча — ошибка. Это работает и в монохромном template-трее macOS.
- **B «Призма».** Белый луч расщепляется на янтарный (через туннель) и голубой (напрямую) — цвета совпадают с семантикой интерфейса. Выразительно, но в 16 px перегружено и напоминает обложку Pink Floyd.
- **C «Шеврон 2.0».** Эволюция текущего знака без рамки и черты. Меньше всего изменений, но по-прежнему близко к «>_», а узнаваемости, которую стоило бы сохранять, у продукта до релиза нет.

**Движение** (замена DS §11, токены в таблице стенда):

- **Переходы между разделами** показывают направление: ниже по списку — содержимое входит снизу, выше — сверху (сдвиг 12 px, 280 мс, вход с шагом 32 мс); выход короче входа (120 мс). Индикатор активного пункта навигации перетекает между пунктами, а не перескакивает.
- **Диалоги растут из кнопки**, которая их открыла (container transform), и сворачиваются обратно; панель профиля выезжает со своего края, её содержимое появляется лесенкой.
- **Между окнами**: заставка холодного старта (сборка знака, только если ядро стартует дольше 300 мс), «показать из трея» (содержимое 0,985 → 1, 220 мс), мини-режим ↔ полное окно через View Transitions API с откатом на CSS. Нативную рамку анимирует ОС, мы анимируем только содержимое.
- **Хореография подключения**: луч течёт пунктиром → при успехе прорисовывается, зеркало вспыхивает, фотон «прыгает» на место пружиной, по фону проходит одна волна; при разрыве луч рвётся, фотон краснеет, тост с обратным отсчётом переподключения.
- **Фон «световое поле»**: два медленных луча и «пол» цвета бренда под углом −16° и −23°, статичное зерно 6 % против полос. Интенсивность привязана к состоянию (0,45 отключено, 0,95 подключение, 0,75 подключено, 0,30 ошибка); тонкие «фотоны трафика» пролетают не чаще раза в 4 с при скорости выше 300 КБ/с. Только `transform` и `opacity`, ноль циклов `requestAnimationFrame`, пауза при скрытом окне и вне экрана, выключено при «Сократить движение», в режиме экономии батареи и в веб-панели по умолчанию. Пользовательская настройка: Выкл / Тихая / Живая.
- **Сокращённое движение**: все сдвиги и масштабирование заменяются сменой прозрачности за 120 мс, хореография сразу показывает финальное состояние, фон выключен. Стенд позволяет включить это вручную и замедлить всё до 0,2×.
- **Без новых зависимостей**: CSS, View Transitions API там, где он есть (WebView2; WKWebView начиная с Safari 18; WebKitGTK — проверить версии в Ubuntu 22.04/24.04), FLIP-утилита на ~40 строк. framer-motion не нужен.

Что поменять в DS: §1 (концепция знака → направление A), §2 (градиент разрешён знаку и лучу-индикатору — без изменений; убрать «рамку-градиент» из §8), §11 (заменить таблицей токенов движения из стенда), §12 (добавить forced-colors и правило «состояние не только цветом»).

## 6. Чего не хватает целиком

**Экраны и разделы**
- Вход в веб-панель, сессии, смена пароля.
- Соединения в реальном времени (процесс, домен, правило, исходящий, «закрыть», «создать правило»).
- Диагностика: «Почему не работает?», проверка утечек, проверка маршрута.
- Цепочки прокси и управление группами.
- Настройки TUN (стек, MTU, strict route, исключения), авторизация входящего прокси, LAN-доступ с паролем.
- Режим шлюза OpenWrt: устройства LAN и политики на устройство.
- Мастер переноса из NekoBox; резервная копия и восстановление.
- «О программе → Лицензии» (GPL, список компонентов).
- Мини-режим и меню трея (с поиском серверов).

**Состояния**
- Пустые: 0 серверов, 0 подписок, 0 правил, пустой журнал.
- Ошибки: ядро не запустилось, нет сети, captive portal, подписка вернула 0 серверов или ошибку, конфликт порта, нет прав для TUN, отказ UAC.
- Загрузка и прогресс: тест задержки и полный тест, импорт, обновление подписок, установка обновления с перезапуском.
- Переходные: подключение, переподключение после разрыва с обратным отсчётом, безопасный режим запуска.
- Веб-режим на телефоне и планшете; режим высокой контрастности.

**Модули**
- Привилегированный помощник для трёх ОС и «страж» восстановления после краша.
- TUF-lite обновления: метаданные, зеркала, загрузчик, rollback-помощник; подписанные пресеты и geo.
- Импортёр NekoBox и миграции схемы данных.
- Санитайзер логов (redaction), SSRF-безопасный fetcher подписок.
- Платформенный адаптер с флагами возможностей (что доступно в приложении, а что в веб-режиме).
- Генератор иконок и трей-ассетов (концепт и SVG в `design/concepts/`).

**Документы**
- `TEST-PLAN.md` с бюджетами производительности.
- `THREAT-MODEL.md` (API, помощник, подписки, обновления, веб-панель) и `SECURITY.md`.
- `UPDATE-SYSTEM.md` v2 (TUF-lite, зеркала, OpenWrt opkg + apk, откат, подписанные пресеты).
- `OPENWRT-GATEWAY.md` (nftables, dnsmasq, IPv6, watchdog, архитектуры, требования к железу).

## 8. Вердикт

**Не готов к утверждению как полный дизайн. Визуальное направление можно утвердить уже сейчас.**

Палитра v1.1 («графит и янтарный луч», «бумажная пастель»), типографика и библиотека компонентов — хорошая база: спокойно, профессионально, без «ИИ-шлейфа», reduced motion учтён. Но утверждать прототип как спецификацию для разработки нельзя: главный экран не показывает текущий сервер, онбординг не ведёт к подключению, веб-режим не работает на телефоне и не имеет входа, контрастные токены нарушают WCAG AA во всех экранах, отсутствуют целые MUST-функции и все пустые и ошибочные состояния. Это исправимо в рамках этапа дизайна, ориентировочно 1–2 недели работы.
