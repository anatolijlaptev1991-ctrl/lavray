# M14. Kill switch системного прокси и транспорт XHTTP (хвосты B)

| Поле | Значение |
|---|---|
| ID | M14 |
| Слой | ручной (человек; агент с computer-use выполняет части кроме принудительной остановки ядра, её делает PowerShell) |
| Время | 50–70 минут |
| Зависимости | M01, M03 (рабочий сервер и привычка читать реестр прокси), M06 (уведомления). Автоматика: A09 (раздел 9, XHTTP по API); A11 (ядро и оболочка без kill switch); Rust-тесты `shell/src/killswitch.rs` в A04 |
| Опасность | **прокси и принудительная остановка ядра**: часть 2 намеренно оставляет системный прокси включённым на мёртвом порту; интернет в браузерах пропадает до шага «Снять прокси». Только тестовый ПК (`C:\lavray-test\TESTPC_OK`) |

> **Предупреждение.** Если что-то пошло не так и прокси остался включённым, выполните откат (часть 7): `reg import C:\lavray-test\tmp\M14-before.reg`.

## Цель

Проверить, что настройка «Не снимать прокси при падении ядра» работает так, как обещает подпись: при смерти ядра системный прокси остаётся, браузеры получают отказ, а не уходят напрямую; пользователь узнаёт об этом (значок трея, уведомление, баннер «Снять прокси»); состояние переживает перезагрузку окна; «Отключить» и выход из приложения снимают прокси всегда; с выключенной настройкой падение ядра прокси снимает, как раньше. Проверить также транспорт XHTTP: ссылка импортируется и сохраняется, профиль помечен «не поддерживается ядром», подключение (в том числе через цепочку) даёт понятную ошибку `transport_unsupported`, правка профиля не теряет режим и `extra`, новым профилям XHTTP в редакторе не предлагается.

## Предусловия

- Тестовый ПК подтверждён; установлена версия `<TAG>` (по умолчанию `v0.9.0`; на момент написания — `main` на `773b4e8`); в программе есть рабочий сервер (M03, часть 1). Порт 2080 свободен.
- Исходное состояние реестра сохранено:

  ```powershell
  New-Item -ItemType Directory -Force -Path C:\lavray-test\tmp | Out-Null
  reg export "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" C:\lavray-test\tmp\M14-before.reg /y
  Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' | Select-Object ProxyEnable, ProxyServer, AutoConfigURL | Format-List
  ```

  Запишите значения «до». Дальше «исходное» означает именно их.
- Функция чтения прокси из PowerShell (используется во всех частях):

  ```powershell
  function Get-Proxy { (Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings') | Select-Object ProxyEnable, ProxyServer }
  ```
- В «Настройки» → «Общие» включены «Уведомления» (M06, часть 3), иначе шаг 2.6 получает `SKIPPED`.
- Браузер Edge или Chrome (используют системный прокси). `curl.exe` системный прокси **не** читает, для проверки используйте браузер или `Invoke-WebRequest`.

## Часть 3. «Отключить» и выход снимают прокси всегда

Настройка по-прежнему включена.

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 3.1 | «Подключиться», затем обычное «Отключить» | `Get-Proxy` → исходные значения; баннера нет | |
| 3.2 | «Подключиться», `taskkill /F /IM lavray-core.exe` (баннер появился, прокси оставлен), затем «Подключиться» снова | Баннер исчезает, прокси смотрит на новое живое ядро (`ProxyEnable = 1`), страницы открываются | |
| 3.3 | `taskkill /F /IM lavray-core.exe` ещё раз (прокси оставлен), затем меню в заголовке → «Выход» | Приложение закрывается; `Get-Proxy` → **исходные значения** (выход снимает прокси даже при включённой настройке) | |
| 3.4 | Запустите приложение, «Подключиться», `taskkill /F /IM lavray-core.exe`, затем «Отключить» (если кнопка доступна) либо «Снять прокси» | Прокси снят, `Get-Proxy` → исходные значения | |
| 3.5 | Выход через меню трея «Выход» при живом подключении | Прокси снят, процессы `lavray*` исчезли (`Get-Process lavray* -ErrorAction SilentlyContinue` пусто) | |

## Часть 5. TUN: подпись «Строгая маршрутизация (strict_route)»

Только с `LAVRAY_ALLOW_TUN=1` и права администратора (M03, часть 6); иначе шаги 5.2–5.4 — `SKIPPED`.

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 5.1 | «Настройки» → «TUN» | Строка **«Строгая маршрутизация (strict_route)»** (раньше была «Принудительный строгий маршрут (kill switch)»), описание «Принудительно включает strict_route, даже если «Строгий маршрут» выключен: трафик не обходит туннель, пока он поднят. Когда ядро падает, адаптер исчезает и блокировки нет; для режима прокси есть настройка «Не снимать прокси при падении ядра».» Отдельная строка «Строгий маршрут» тоже есть | |
| 5.2 | Включите «Строгая маршрутизация (strict_route)», подключитесь в режиме TUN | Адаптер `lavray-tun` есть (`Get-NetAdapter -Name lavray-tun`) | |
| 5.3 | Остановите ядро (`taskkill /F /IM lavray-core.exe`) | Адаптер исчезает; баннера «Снять прокси» **нет** (kill switch прокси относится только к режиму системного прокси; в TUN туннель живёт в процессе ядра и исчезает вместе с ним) | |
| 5.4 | Запишите наблюдение | Полная блокировка трафика при падении туннеля (WFP) не реализована (исследование R-1 плана): трафик после падения идёт по системным маршрутам | |

## Часть 6. XHTTP

Ссылка для проверки (тестовые данные, адрес из документационной сети; подключиться к нему нельзя и не нужно):

```text
vless://11111111-2222-4333-8444-555555555555@203.0.113.50:443?type=xhttp&mode=auto&extra=%7B%22xPaddingBytes%22%3A%22100-1000%22%7D&security=tls&sni=x.example&path=%2Fxh&host=cdn.example#m14-xhttp
```

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 6.1 | «Серверы» → «Импорт» → «Ссылка», вставьте ссылку, дождитесь предпросмотра (не нажимая «Импортировать») | В предпросмотре предупреждение: **«Серверов с транспортом XHTTP: 1. Они будут сохранены, но подключиться к ним пока нельзя: ядро этот транспорт не поддерживает.»** Сервер `m14-xhttp` в списке предпросмотра | |
| 6.2 | Импортируйте | Сервер `m14-xhttp` появился в списке, **не отвергнут** | |
| 6.3 | Строка сервера | Жёлтый значок **«XHTTP: не поддерживается ядром»**; подсказка к нему «Сервер сохранён, но подключиться к нему пока нельзя: в ядре нет этого транспорта. Выберите другой сервер.» У обычных серверов значка нет | |
| 6.4 | Выберите `m14-xhttp`, «Подключиться» | Подключение не начинается; сообщение **«Ядро не поддерживает транспорт этого сервера (XHTTP). Выберите другой сервер.»**; состояние «Отключено»; `Get-Proxy` без изменений | |
| 6.5 | Создайте цепочку: «Серверы» → добавьте сервер типа «несколько серверов подряд», «Добавить узел» — `m14-xhttp` и любой обычный сервер, сохраните как `m14-chain`; у самой цепочки значка «не поддерживается ядром» нет. Выберите её и «Подключиться» | То же сообщение «Ядро не поддерживает транспорт этого сервера (XHTTP). Выберите другой сервер.»: цепочка с XHTTP внутри не собирается молча | |
| 6.6 | Откройте `m14-xhttp` в редакторе: транспорт | В списке «Транспорт» выбран **XHTTP** (не TCP): иначе правка подменила бы транспорт при сохранении | |
| 6.7 | Измените только имя на `m14-xhttp-2`, «Сохранить»; откройте редактор снова | Транспорт остался XHTTP, значок «XHTTP: не поддерживается ядром» на месте | |
| 6.8 | Строка сервера → «Копировать ссылку», вставьте в блокнот | Ссылка содержит `type=xhttp`, `mode=auto`, `extra=%7B%22xPaddingBytes%22%3A%22100-1000%22%7D` (режим и extra сохранились после правки) | |
| 6.9 | «Серверы» → добавить новый сервер (пустой редактор) → список «Транспорт» | Вариантов XHTTP **нет** (новому профилю его не предлагают: ядро всё равно не соберёт) | |
| 6.10 | Импортируйте скопированную в 6.8 ссылку ещё раз (предпросмотр) | То же предупреждение и тот же значок: круг «ссылка → профиль → ссылка» не теряет `mode` и `extra` | |

## Часть 7. Откат

Выключите «Не снимать прокси при падении ядра» (если нужно), удалите серверы `m14-*` и цепочку, убедитесь, что `Get-Proxy` равен исходным значениям, иначе `reg import C:\lavray-test\tmp\M14-before.reg`. Закройте LAVRay, проверьте `Get-Process lavray* -ErrorAction SilentlyContinue` (пусто).
