# LAVRay Update System — спецификация v1.0

Подсистема автообновлений LAVRay: приложение ↔ свои репозитории + обновление ядра sing-box.
Раздел «как устроено в форке сейчас» дополняется из AUDIT.md (агент-аудит); здесь — целевая архитектура.

## 1. Принципы

1. **Никогда не ломать работающий туннель**: обновление применяется только по явному действию пользователя или в спокойном состоянии (не в момент активной сессии, если не подтверждено).
2. **Целостность обязательна**: артефакт без валидной подписи и чексуммы не применяется никогда. Ошибка проверки = безопасный отказ + уведомление.
3. **Откат всегда возможен**: предыдущая версия сохраняется; неудачное обновление автоматически откатывается.
4. **Прозрачность**: пользователь видит, что обновится (приложение / ядро / пресеты / geo-данные), changelog на своём языке, источник-репозиторий.
5. **Каналы**: `stable` (по умолчанию) и `beta`. Смена канала — явное действие.

## 2. Каналы распространения

| Платформа | Хранилище | Механизм применения |
|---|---|---|
| Windows | GitHub Releases `lavray-windows` | Tauri Updater (NSIS): скачать → проверить → установить → рестарт |
| Linux | GitHub Releases `lavray-linux` | `.deb`: apt-репозиторий (GitHub Pages) + `apt upgrade`; AppImage: встроенный updater (замена файла + рестарт) |
| macOS | GitHub Releases `lavray-macos` | Tauri Updater + подпись/notarization; отказ при отсутствии подписи |
| OpenWrt | GitHub Releases `lavray-openwrt` (feed) | opkg-feed (`/etc/opkglavray.conf` → GitHub Pages raw-канал); LuCI-страница показывает доступные обновления, `opkg upgrade` от имени пользователя |
| Пресеты/geo | GitHub Releases `lavray` | внутренний updater ресурсов (JSON-манифесты), без перезапуска приложения |

## 3. Манифест `latest.json` (плюс `beta.json`)

Публикуется в каждом платформенном репо (корень Releases-ассетов и зеркало на GitHub Pages):

```json
{
  "version": "1.2.0",
  "channel": "stable",
  "releasedAt": "2026-11-01T10:00:00Z",
  "minUpgradeFrom": "1.0.0",
  "core": { "name": "sing-box", "version": "1.14.1-neko.1", "required": false },
  "assets": {
    "windows-x64": {
      "url": "https://github.com/.../LAVRay-1.2.0-x64-setup.exe",
      "signature": "minisign-подпись (ed25519)",
      "sha256": "…",
      "size": 12345678
    }
  },
  "notes": { "ru": "…", "zh": "…", "en": "…", "es": "…", "de": "…" },
  "mandatory": false
}
```

Правила:
- `signature` — MinSign (ed25519) поверх артефакта; публичный ключ зашит в приложение и меняется только с major-версией (key rotation — через двойное подписание в переходный период).
- `sha256` — быстрая проверка + защита от битой загрузки; подпись — авторитетная.
- `notes` — локализованные заметки; markdown, экранируются при рендере.
- `minUpgradeFrom` — если текущая версия ниже, требуется цепочка обновлений (для будущего).
- HTTPS-only; URL'ы только на github.com/githubusercontent.com (пиннинг в коде валидатора).

## 4. Поведение приложения

- Проверка: при старте (через 5с, не блокируя UI) + каждые 6 часов + вручную («Проверить обновления»).
- Ответ: сравнение semver (приложение и ядро отдельно), показ в «Центре обновлений» + мягкий бейдж в сайдбаре.
- Установка приложения: скачать во временную папку → проверить sha256 → проверить подпись → прогресс в UI → (Win/macOS) Tauri Updater применяет с сохранением прошлой версии → рестарт с предложением; (AppImage) замена файла atomically (rename) → рестарт; (.deb) показ инструкции `apt upgrade` + кнопка запуска через pkexec/терминал.
- Откат: каталог `updates/previous/` хранит одну прошлую версию; «Откатиться» в Центре обновлений; при провальной установке (не поднялось после рестарта — heartbeat-флаг на первом запуске) — автозапуск отката до входа в UI.
- Обновление ядра (bundled): приходит вместе с приложением (связка версий) — отображается как «ядро обновится вместе с приложением». Отдельная загрузка ядра без обновления приложения не допускается (целостность связки).
- Обновление пресетов/geo: независимые мини-манифесты (`presets.json`, `geo.json`); если пользователь правил пресет — merge-диалог с diff, никогда молча.

## 5. OpenWrt-специфика

- Feed: `src/gz lavray https://anatolijlaptev1991-ctrl.github.io/lavray-openwrt/feed/<arch>` (пакеты `lavrayd`, `luci-app-lavray`, `lavray-webui`).
- Веб-панель/LuCI: блок «Обновления» = версия + кнопка «Проверить» + список пакетов с версиями; применение — `opkg upgrade` через rpcd-скрипт от root; перед применением создаётся snapshot конфигов (`/etc/lavray/backup`), откат — восстановление конфигов + `opkg install <старая версия>` (прошлые .ipk кэшируются в feed, минимум 2 последние версии).
- Конфиги пользователя (UCI + JSON) не затираются пакетом (conffiles в control).

## 6. Процесс обновления ядра sing-box (policy, не код)

1. Ежесуточный GitHub Action в репо `lavray`: проверка нового upstream-релиза SagerNet/sing-box → черновик issue+ветка.
2. Гейт обновления (строгий, по Доктрине): аудит changelog + breaking changes API → проверка лицензии upstream (обязательная — лицензия sing-box менялась) → перенос neko-патчей (список патчей ведётся в `core/NEKO_PATCHES.md`) → полный L1 (тесты, фаззинг, бенчмарки) + L2 adversarial-ревью → smoke-тесты коннективности на всех протоколах в CI-матрице → рекурсия до нуля замечаний → тег `core-<version>` → включается в следующий релиз приложения с пометкой в changelog.
3. Даунгрейд ядра запрещён без даунгрейда приложения (связка версий).

## 7. Тестирование подсистемы (обязательный минимум в CI)

- Юнит: semver-сравнение, парсинг манифеста, валидация подписи (позитив/негатив: битая подпись, чужой ключ, truncated-файл), URL-пиннинг.
- Интеграционные: обновление поверх предыдущей версии (Win/macOS/Linux контейнеры), битый артефакт → отказ + откат, отсутствие сети → деградация к «нет обновлений», rollback-флаг после неудачного рестарта.
- OpenWrt: feed-индекс валиден, `opkg install`/`upgrade` в контейнере SDK, conffiles сохранены, откат на прошлую версию.
- E2E UI: баннер → Центр обновлений → прогресс → рестарт-заглушка (в тестовом окружении).
