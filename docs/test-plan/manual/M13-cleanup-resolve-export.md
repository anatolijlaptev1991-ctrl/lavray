# M13. Очистка серверов, действия меню строки, «Обновить все», откат подписки, настройки (хвосты A и B)

| Поле | Значение |
|---|---|
| ID | M13 |
| Слой | ручной (человек; агент с computer-use выполняет части 1, 3 и 4 по снимкам экрана) |
| Время | 60–80 минут: части 1–3 около 30 минут, часть 4 около 40 минут |
| Зависимости | M01, M02 (серверы, подписка), M03 для части 4.11 (подключение к рабочему серверу), M04 для 4.10 (трафик). Автоматика: A09 (раздел 5) проверяет все RPC хвостов A по API; A01 и A05 проверяют, что у каждого RPC есть место в интерфейсе (`rpc_usage`) |
| Опасность | нет для частей 1–2 и 4.1–4.9; часть 3 и шаг 4.11 подключаются к рабочему серверу и **включают системный прокси** (отключайтесь после проверки, тестовый ПК обязателен) |

## Состояние интерфейса

Хвосты A дали ядру RPC очистки, дубликатов, разрешения доменов, выгрузки конфига, сброса настроек; хвосты B (в `main` с `773b4e8`) добавили для них интерфейс: пункты меню строки сервера, диалог «Очистка серверов», кнопки «Обновить все» и «Откатить» в «Подписках», сводку трафика группы и карточку «Текущий конфиг ядра» в диагностике. Подписи в этом файле взяты из `ui/src/lib/dictionaries/ru.ts` того же коммита. Защиту «RPC есть, а кнопки нет» проверяют A01 (шаг 15, `rpc_usage.py`) и A05 (`rpc-usage.test.ts`).

## Цель

1. Проверить, что понятие «недоступный сервер» в списке («Недоступные») и в очистке совпадает. Первый прогон части 2 нашёл расхождение (очистка считала недоступным только профиль с задержкой `< 0`, а проверка записывает лишь текст ошибки); оно исправлено в `470d5f2`, в `main` с `80be1e9`. Шаг 1.3 остаётся защитой от регресса.
2. Проверить читателей настроек, видимых пользователю: размер буфера журнала (`ui.max_log_lines`, диапазон 100–50 000, по умолчанию 1000).
3. Проверить поведение «запоминания профиля» (`remember.id`, `remember.modes`) в приложении: после подключения и перезапуска выбранный сервер и режим сохраняются.
4. Проверить действия хвостов B в интерфейсе: меню строки (перенос в группу, дубль, сброс трафика, замена домена на IP, экспорт конфига с предупреждением о секретах), диалог очистки с пробным прогоном, «Обновить все», откат подписки, сводку трафика группы, конфиг ядра без секретов.

## Предусловия

- Установленная версия `<TAG>` (по умолчанию `v0.9.0`; на момент написания — `main` на `773b4e8`, ветка `feat/tails-b`, `1739602`, то же дерево).
- Три сервера-пустышки: «Серверы» → «Импорт» → «Ссылка»: `socks://127.0.0.1:1#m13-dead-1`, `socks://127.0.0.1:2#m13-dead-2`, `socks://127.0.0.1:3#m13-dead-3` (порты закрыты, подключиться нельзя).
- Для части 2 — запуск ядра с веб-панелью (см. M16, часть 1) и `curl.exe`.

## Безопасность

Системные настройки не меняются. Серверы-пустышки удаляются в части 5.
