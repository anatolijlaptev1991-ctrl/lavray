# M04. Экран «Соединения», скорость и учёт трафика

| Поле | Значение |
|---|---|
| ID | M04 |
| Слой | ручной (человек или агент с управлением экраном) |
| Время | 25–35 минут |
| Зависимости | M03 (рабочее подключение через системный прокси). Выполняется последовательно после M03 |
| Опасность | **прокси** (как в M03): в сеансе включается системный прокси |

> **Предупреждение. Файл включает системный прокси. Запускать только на тестовом ПК. Маркер `C:\lavray-test\TESTPC_OK` обязателен.**

## Цель

Проверить живую картину трафика (T-79): вкладка «Соединения», скорость в строке состояния и на графике, учёт трафика по серверу, пауза и фильтры, закрытие соединения, поведение при обрыве потока, очистка при отключении и учёт после аварийной остановки ядра. Живая проверка Ф1 из плана: скорость не 0; «Соединения» показывают байты и правило; «Закрыть» обрывает загрузку; пауза замораживает список; после отключения история пуста; трафик профиля растёт; потеря учёта при падении ядра не больше 30 секунд.

## Предусловия

- Работает подключение через системный прокси к рабочему серверу (M03, части 1–2).
- Для крупной загрузки нужен файл большого размера по ссылке, например `https://speed.hetzner.de/100MB.bin` (любой публичный файл от 50 МБ). Загрузка идёт через системный прокси: PowerShell 7 `Invoke-WebRequest` его использует.
- Доступ к Диспетчеру задач для проверки процесса ядра.

## Безопасность

Откат: «Отключить» и проверка реестра (как M03, п. 5.2). Загруженные файлы удаляются.

## Часть 1. Скорость и график

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 1.1 | Подключитесь (Ctrl+D также переключает подключение), откройте «Подключение» | В покое: график «График скорости» пуст с подписью «Подключитесь, чтобы видеть скорость» только если отключено; при подключении кривая 0 | |
| 1.2 | В pwsh 7: `Invoke-WebRequest https://speed.hetzner.de/100MB.bin -OutFile C:\lavray-test\tmp\M04-dl.bin -UseBasicParsing` (повторить при ошибке) | Загрузка идёт | |
| 1.3 | Во время загрузки смотрите строку состояния и график | Скорость «Загрузка» отлична от 0 (в «КБ/с», «МБ/с»), на графике видна кривая; «Трафик за сессию» растёт | |
| 1.4 | После окончания загрузки | Скорость возвращается к нулю; «Трафик за сессию» остаётся большим (не меньше размера файла) | |

## Часть 2. Экран «Соединения»

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 2.1 | «Диагностика» (Ctrl+4) → вкладка «Соединения» | Заголовок таблицы «Активные соединения», счётчики «Активных: N» и «Закрытых: N»; чипы «Все», «Прокси», «Напрямую», «Блок» (подпись группы «Тип соединения»); поле «Поиск по соединениям…»; кнопка «Пауза» | |
| 2.2 | Колонки таблицы | «Приложение», «Адрес», «Сеть», «Исходящий», «Правило», «↓ / ↑», «↓ Загружено», «↑ Отдано», «Длительность», «Статус» | |
| 2.3 | Запустите длинную загрузку (п. 1.2) и откройте несколько сайтов | В таблице появляются строки с адресами; «Исходящий» показывает сервер (и цепочку, если есть) или «Напрямую»; «Правило» называет правило пресета; байты растут | |
| 2.4 | Статус строк | «Активно» у открытых, «Закрыто» у завершённых (остаются в истории, до 1000 штук, пока открыт экран) | |
| 2.5 | Чип «Прокси» | Остаются соединения через сервер | |
| 2.6 | Чип «Напрямую» (откройте локальный/российский сайт, который идёт напрямую по пресету) | Остаются прямые соединения | |
| 2.7 | Чип «Блок» | Остаются заблокированные (рекламные домены пресета), если были | |
| 2.8 | Чип «Все», в «Поиск по соединениям…» введите часть адреса | Список фильтруется без учёта регистра; если ничего нет: «Ничего не найдено» | |
| 2.9 | «Пауза» | Список замораживается, появляется «Список заморожен»; кнопка меняется на «Продолжить»; новые соединения не добавляются | |
| 2.10 | «Продолжить» | Список снова обновляется | |
| 2.11 | Меню строки (кнопка в колонке «Действия») → «Копировать адрес» | Сообщение «Адрес скопирован»; в буфере адрес (`Get-Clipboard`) | |
| 2.12 | Запустите долгую загрузку (п. 1.2) и в меню её строки выберите «Закрыть соединение» | Загрузка обрывается ошибкой в pwsh; сообщение «Соединение закрыто»; строка получает статус «Закрыто» | |
| 2.13 | Без активных соединений (подождите, закройте браузер) | Подсказка «Пока нет соединений — они появятся, как только приложения начнут работать с сетью» (при подключении) | |
| 2.14 | «Отключить», вернитесь на «Соединения» | «Нет активных соединений — подключитесь, чтобы увидеть, куда идёт трафик»; история закрытых пуста | |
| 2.15 | Подключитесь заново | Таблица заполняется с нуля, без старых строк | |

## Часть 3. Обрыв потока данных

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 3.1 | На экране «Соединения» убейте ядро: `Get-Process lavray-core \| Stop-Process -Force` (на установленной версии путь `C:\Program Files\LAVRay\binaries\lavray-core.exe`) | Экран показывает сообщение «Переподключение выполняется автоматически»; оболочка перезапускает ядро; в течение минуты поток восстанавливается без перезапуска окна | |
| 3.2 | Системный прокси после гибели ядра | Снят (реестр как до теста): оболочка возвращает прокси при смерти ядра | |
| 3.3 | Подключитесь снова | Данные на экране «Соединения» идут | |

## Часть 4. Учёт трафика профиля и потеря при падении

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 4.1 | «Серверы»: запишите значение трафика у активного сервера (колонка/подпись объёма) | Число (может быть 0 или «—», если сервер новый) | |
| 4.2 | Загрузите файл ≥ 50 МБ (п. 1.2), подождите 35 секунд | Трафик сервера вырос; учёт сохраняется каждые 30 секунд | |
| 4.3 | «Отключить» | Значение сохранено (сохраняется при отключении) | |
| 4.4 | Подключитесь, загрузите ещё файл, **сразу** убейте ядро (`Stop-Process -Force`) | После перезапуска ядра значение трафика сервера не меньше значения п. 4.3 плюс загруженное минус не более последних 30 секунд | |
| 4.5 | Перезапустите программу (Меню → «Выход» и снова) | Значения трафика не обнулились | |
| 4.6 | Сброс учёта: меню строки сервера → «Сбросить трафик» (если пункт есть в версии) | Значение обнуляется; в противном случае отметьте «пункта нет в этой версии» | |

## Часть 5. Скорость в строке состояния при коротких соединениях

| № | Действие | Ожидаемо | Результат |
|---|---|---|---|
| 5.1 | Выполните 20 коротких запросов подряд: `1..20 \| ForEach-Object { Invoke-WebRequest https://example.com -UseBasicParsing \| Out-Null }` | Скорость в строке состояния показывает всплеск (считается весь трафик, включая короткие соединения, которые не успели попасть в список) | |

## Критерии PASS/FAIL

| № | Критерий | Шаги |
|---|---|---|
| К1 | Скорость и график отличны от 0 при загрузке, «Трафик за сессию» растёт | 1.3–1.4 |
| К2 | Таблица «Соединения»: колонки, чипы, поиск, статусы | 2.1–2.8 |
| К3 | Пауза замораживает список и снимается | 2.9–2.10 |
| К4 | «Копировать адрес» и «Закрыть соединение» работают; закрытие обрывает загрузку | 2.11–2.12 |
| К5 | После отключения история пуста, при подключении таблица новая | 2.14–2.15 |
| К6 | Обрыв потока: сообщение, автопереподключение, прокси снят после гибели ядра | 3.1–3.3 |
| К7 | Учёт трафика сохраняется при отключении и выходе, потеря при аварии не больше 30 с | 4.2–4.5 |

## Что собрать

Скриншоты: график и скорость во время загрузки, экран «Соединения» с данными, с паузой, пустой, с сообщением об обрыве. Значения трафика из п. 4.1–4.5.

## Откат / уборка

«Отключить»; проверка реестра (M03, п. 5.2); `Remove-Item C:\lavray-test\tmp\M04-dl.bin`; убедитесь, что `Get-Process lavray-core` соответствует ожидаемому (после выхода — нет).

## Отчёт

`results/M04.md` по `templates/REPORT.md`; шаги — номера таблиц. Провал К1 (скорость 0 при трафике) — `major`; К4 (закрытие не обрывает загрузку) — `major`; К6 (прокси остался после гибели ядра) — `critical`; К7 — `major`.
